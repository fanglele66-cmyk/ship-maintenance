# Windows 本地启动脚本

此目录保存智能机舱父目录使用的启动脚本。更新本地入口时，将本目录的 `start-local.ps1`、`stop-local.ps1` 和两个 `.cmd` 文件复制到 `ship-maintenance` 的父目录，保持如下结构：

```text
智能机舱目录/
  启动智能机舱.cmd
  停止智能机舱.cmd
  start-local.ps1
  stop-local.ps1
  ship-maintenance/
    phase2-demo/
  shore-ship-maintenance/       # 只启动船端时不需要
```

双击启动入口会检查前端构建并启动船端 `http://127.0.0.1:5173/`。需要 Node.js 24、npm、Python 和已安装的项目依赖；时序数据和模型配置按各部署说明准备。

## 代码更新后的行为

- 对 `server`、`src`、`data` 和依赖清单记录内容指纹。重复启动时，代码未变化则复用现有进程，代码变化则重启本脚本登记的船端后端。
- 旧登记记录没有指纹时，首次运行新版脚本会重新加载后端。前端构建失败时保留原服务。
- 运行数据库、模型凭据和生成报告不计入指纹，日常数据写入不触发重启。
- 停止或重启前核对 PID、进程创建时间、程序路径及完整命令行；不结束其他项目的进程。
- 重启保留账号、会话和业务数据。正在生成的 AI 请求会中断，页面可重新生成；正式回执不需要重复填写。

日志和进程记录保存在父目录 `.runtime`。容器部署仍使用 `phase2-demo/Dockerfile`，不使用这些 Windows 脚本。

