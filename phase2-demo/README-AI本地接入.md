# 本地模型与报告补充

本轮新增功能仅在本地开发服务启用，未包含在 2026-10-29 发布的第 25 版站点中。GitHub 发布基线为 `733ed6f`；Sites 对应源码提交为 `73c3b2799857ba60dd09e5153a74741437f97dfe`。

## 启动与配置

使用 Node.js 24，运行现有的“启动智能机舱.cmd”，或在此目录执行 `npm run dev`。本地页面为 `http://127.0.0.1:5173`。后端由 Vite 开发服务加载，无需单独启动进程；`npm run build` 只产出前端静态文件，不包含模型服务。

模型仅通过后端文件配置，前端没有设置按钮、配置页面或配置读写接口。

编辑本机 `.local-ai/config.json`（已创建）；可参考 `server/ai-config.example.json`。默认选择 CC Switch 的“DeepSeek”（当前模型 `deepseek-v4-flash`）；`model` 和 `baseUrl` 留空时跟随该供应商配置。原 GLM（众数个人用）默认供应商 ID 已在 `server/ai-config.mjs` 中注释保留，本机原配置备份为 `.local-ai/config.glm-disabled.json`；恢复时可复制备份覆盖 `config.json`。后端只读 `%USERPROFILE%/.cc-switch/cc-switch.db`，不切换或修改 CC Switch。可用 `CC_SWITCH_DB` 环境变量指定数据库路径。

可配置 `enabled`、`source`、`providerId`、`model`、`baseUrl`、`protocol`、`maxTokens`、`timeoutMs` 和 `knowledgeEnabled`，每次请求读取最新文件，无需重启。`source` 为 `manual` 时，在本机文件中加入 `apiKey`，并填写模型、地址和协议（`anthropic` 或 `openai`）。密钥不返回给页面，不进入前端包；`.local-ai` 已排除 Git，并禁止通过 Vite 文件服务访问。

在此目录运行 `npm run ai:test` 检查真实连接，输出供应商、模型、回答和 Token 用量，不输出密钥。

模型接口仅允许本机同源页面请求，带固定客户端标记以阻止跨站请求。当前角色切换仍是原型的前端视角控制，不是多用户身份认证；公开部署这套后端前需接入真正的登录、角色授权和共享报告存储。

## 问答与资料引用

右侧助手使用真实模型回答普通问题，保留已有规则建议和历史对话。页面不显示模型名称。回答采用流式输出；接口异常时明确显示失败原因，普通问答尚未输出正文时可返回现有规则建议，已输出的部分保留并标明中断；报告修订失败时不修改报告。

`wiki_rt-flex50` 中的 Markdown 由后端按章节切片、关键词检索，附文件路径、行号及原文。知识库不拷贝到公开静态包。当前共 63 篇文档、859 个片段；图片和 PDF 不参与识别。资料中的历史案例仅是参考，不能自动作为本次现场故障证明。

接口格式依据 [Anthropic API 概览](https://platform.claude.com/docs/en/api/overview)及[流式输出文档](https://platform.claude.com/docs/en/build-with-claude/streaming)。后端以 `stream: true` 请求，支持 Anthropic 和 OpenAI 兼容 SSE；仅转发可展示文本，不取模型内部推理内容。

## 提交后补充报告

执行人提交排查、维修或维保报告后，可以在对话框选中“补充报告”和目标报告；再次点击取消选中后就是普通问答。只有按钮选中时才进入修订流程，消息以“补充：”开头也不会自动切换。模型接收已有报告、补充原文与相关资料，返回固定结构的完整结论及四个分析小节。

修订稿的结论和分析随模型输出逐段显示，完整生成且通过结构校验后才显示“确认补充并更新报告”，点击后写入。中断、超时、截断及缺失章节的草稿不能写入；刷新页面后将未完成生成标记为中断。原有报告编号、事件编号、提交时间、负责人、任务范围和逐项记录不变；结论和分析更新，增加提交后补充记录。保留每次修订前版本、补充原文、模型与资料索引，并提醒轮机长重新审阅。关闭的事件不能补充；报告已变化时拒绝应用旧修订稿。

报告仍使用现有浏览器本地存储，刷新后保留；同源其他标签页通过 storage 事件同步。清理浏览器数据会删除这些报告，当前尚无服务器持久化和跨设备同步。

## 派发前任务与决策分支

轮机长在当前阶段的 Tab 栏可提前查看待派发排查、待派发维修或复查任务。任务草稿独立于已派发任务，不会提前进入执行人的待办。点击任务页的“通过对话修改任务”，或在助手中选中“修改待派任务”，可让真实模型修改范围、依据、步骤与回交要求；修改只更新草稿，正式派发仍由轮机长填写负责人和时限后确认。派发采用当前草稿的步骤，并保存草稿来源快照。

后台文件可单独配置 `taskMaxTokens`（默认 8192）与 `taskTimeoutMs`（默认 180000 毫秒），为结构化任务留出完整输出空间；普通回答和报告修订继续使用 `maxTokens`、`timeoutMs`。

排查回交后以最新一轮逐项结果选择分支：有任一“发现异常”“读数不一致”或“偏离仍存在”项，先派发维修；没有异常项则继续排查。“无法确认”等记录作为待核实项纳入下一轮，不视为正常。继续排查由模型依据历轮报告、已排除方向及未确认项自动预生成，不直接复制首轮步骤。模型失败时保留错误与重试入口，未完整生成的后续任务不能派发。

效果观察阶段提供闭环、复查和同步岸基。复查页先显示四步预设任务，同时由 AI 依据实际维修报告、剩余事项及观察记录整理新版；生成成功后整体替换，失败时保留预设并提供重试，轮机长可核对后使用预设。复查后发现异常则进入维修；未见异常则返回效果观察，供轮机长决定闭环或再次复查。复查仍归入排查类报告，标题注明复查。既有维保报告与历史安排保留。

对话修改、报告补充或阶段切换期间，过期的模型响应不能覆盖新草稿或历史任务。任务与报告继续使用本机浏览器存储。

## 自动采样

效果观察按真实使用流程展示，每 2 秒增加时间点、从左到右绘制，按两小时汇总窗口保留记录。开发数据适配器为 `src/mock/lifecycleSampling.js`，对同一事件和任务生成稳定、有限、无未来时间的曲线；内部来源保留为 `prototype`。页面不显示模拟标记。后续接真实遥测时替换该适配器，不将演示曲线当作实船修复证据。

## 岸基同步、作业细化与闭环

各阶段（含维修待派、执行中及闭环后）的处置选项都保留“同步岸基”；仅闭环后显示右上角快捷按钮，存储当时事件、任务、报告与决定的快照，并标记“待岸基接收”。目前没有配置岸基收件接口，不声称远端已收件；同步不会改变当前阶段、待派任务、完成时限或选中的 Tab。

维修草稿包含批准范围、备件/工具、隔离、标识、具体获批处理、复装、试验与交接。缺少厂家参数时要求核对适用作业卡，不编造数值；ICU 内部检修按本地知识库中“厂家认可车间”的边界执行。既有未提交的三步通用维修任务会细化，原表单填写存入 procedureHistory 并可展开查看；新步骤保留空结果，不能将原来一条“完成”推算成多个项目已完成。已提交任务不改写。

闭环报告按基础信息、原始异常、各轮排查及原因、实际维修和用料、修后观察与复查、闭环决定、完整时间线、报告/附件索引组织；保留执行人补充与未确认项。采样仅记录截至闭环的实际保存窗口，不把计划步骤写成已完成，不把趋势回归直接写成故障消除。

流式接口在配置读取与知识检索前先发送接收状态，再发送真实检索和资料摘要、上游开始响应状态及逐段正文。只展示可核对的依据和处理进度，不转发模型隐藏推理。进度响应不等同于模型正文首字延迟改善。

维修可反馈步骤最多 4 项，按作业顺序合并为准备与隔离、实施维修、复装试验、交接观察；具体操作作为组内子步骤完整保留，未减少备件和检验要求。超过 4 项的模型结果同样由任务规范化层合并。进行中的旧维修卡会合并反馈，旧记录原文保存在 feedbackHistory，逐项结果及备注汇入对应组；组内仍有未填写项目时不自动勾选已完成。已提交报告和历史任务保持原样。

## 对话修改任务的约束

排查与复查允许 1—4 个反馈步骤，一项是有效任务，不要求凑够三项。新任务生成与现有任务编辑分别使用 generate/edit 模式：明确“删除第二项、仅保留第一项”同样调用后台配置的大模型，由模型输出原编号的删除操作；保留项的标题、说明、检查要求、回交要求和关联方案原样保留。展示上游返回的真实 Token 用量，不使用本地删除捷径；模型失败时保留原稿。编号越界、含条件或否定、互相矛盾的删除请求保留原稿并提示。

其他修改由模型输出针对原编号的 update/remove/insert 操作，不再返回完整任务重写；后台和前端同时校验指定编号、字段、增删权限及最终数量。未要求新增时不能增加步骤，未涉及的任务保持内容和顺序。失败不会显示“已更新”。成功后显示实际数量变化，保存完整的修改前后快照，任务页可展开查看修改记录。此规则适用于新发起的编辑；既有历史会话不会据此重写。

维修执行页直接展示精简后的逐项操作、记录要求与排查结论，不使用折叠隐藏作业内容。已知模板句合并重复措辞，保留备件核验、隔离卸压、批准范围与复测停止条件；未知或模型补充的要求按原文展示。每步仅保留一处备注输入，反馈与备注并列。现有任务与填写数据不因显示精简而改写。新生成维修方案使用 1—4 个反馈步骤，每步简述方法、检查与停止条件和回交要求，避免再展开 8—10 项通用操作。

已分派事件的轮机员可查看风险提醒阶段的“风险提醒、数据观测、证据资料”。风险提醒仅显示异常现象及关键数据，不渲染决策要点、派发依据、建议排查范围及轮机长决策表单；未分派事件仍不可访问。
