# 控制空气双测点低压核实 · 维修协作脚本

## 实施范围

轮机长审阅排查报告后，选择“派发维修”，核对一号减压阀已定位的密封垫问题，明确 WO-AIR-001 范围。二号供气路径保留，不扩大为全部阀组或空气供给部件更换。切换为大管轮进入维修任务。

两个进口压力通道不是减压阀前后测点；压力回升不等于已修复。独立表、阀前后实测和供气分段核查分别记录。

## 任务开场（整项任务一次）

任务助手先自我介绍：“我是任务助手，可以帮你把现场情况整理成维修备注。”并提示可以说情况、发照片或读数截图。

输入框上方问“这项维修，你想先从哪里开始？”。选择“记录作业情况”后点“确认”，相当于发送：

> 我想先记录这次维修已经做的作业。

助手回应：

> 好，先说说这次维修做了什么、结果怎样；有照片或读数也可以一起发来。

然后按下文发送现场描述。也可直接发送，不必先作开场选择。后续换步仍是同一个助手，不重复此开场。

## 提交与交接

1. 核对全部必填结果和采用后的备注；没有上传的附件仍记待补，不补造数值。
2. 点击左侧 **提交维修报告**；右侧助手保持展开，开场自我介绍不变化。报告生成进度与提交回执另行显示，记录已提交与验证已完成分开。
3. 通过“本轮执行记录／维修报告”页签核对；执行记录按步骤切换，下载按钮下载 Markdown。
4. 本路径有未完成验证，交轮机长选择“等待条件，保留原任务”或继续派发剩余任务；缺少独立校验、完整试验或可比工况资料时，不将提交报告等同于维修有效或事件闭环。

## 使用说明

每个任务只有一个助手。开场只出现一次，切换左侧步骤继续使用本任务对话，不重复开场。左侧不需要 AI 协助按钮；直接在右侧发送即可。附件、图片和语音入口在输入框底部，发送前核对内容。

原话完全匹配时使用固定回复，先展示分段处理进度，再给一句追问或备注草稿。追问等待合计约 1.6 秒，草稿约 1.8 秒；这是处理状态，不是外部模型的推理。脚本外新事实或改写仍调用当前配置的真实模型，并携带本任务上下文；不要把其他步骤内容当成本步已执行证据。

信息不足先追问，不会每次都给草稿。草稿出现后，输入框上方选择“采用到本步骤”，再点“确认”；只写本步备注，不自动选择结果、换步或提交。选择“继续修改”后点“确认”会点亮输入框，再发送补充；在有可选修订的步骤，可使用下文给出的修订原话。

每个主步骤可独立开始，不必完成上一主步骤的可选修订；补充回答仍需本步前文。先选结果再采用、先采用再选结果都可；若结果与描述冲突，助手先简短核对。采用后按橙黄色“下一步”提示手动切换左侧步骤。必填结果齐全时导航变绿，只代表填写齐全。

提交后任务助手最前的两句自我介绍保持不变，报告进度与提交回执在后续消息显示，不向引导语追加状态。报告页仍按现有生成流程工作，固定对话不包含最终报告生成；生成失败时保留已提交事实记录，可重试。

图片仅使用真实上传的本轮材料；已有参考图与来源见 [README](README.md)。脚本外输入转入当前配置的真实模型，最终报告生成也沿用现有流程；本地固定回复不声称执行图片识别或真实模型推理。
