## 直接部署后端镜像时的路径配置

单独运行 Dockerfile 的 `backend` 目标时，Node 也能处理 `/ship-smart-engine-room/`，不依赖另一个前端 Nginx 容器。自定义前缀通过 `SHIP_CONTEXT_PATH` 设置；Compose 会将同一个值传给前后端。

公司代理可以保留完整路径转发给 Node；已经去除前缀的转发仍然兼容。`SHIP_PUBLIC_ORIGIN` 只填写浏览器访问的协议、主机及可选端口，不包含 context-path。容器使用下述网站访问模式，账号登录和角色权限继续生效。

## 公司网站登录与请求来源

2026-11-16 修复：公司反向代理的连接 IP 和内部 Host 与原本本地模式不匹配，导致 `/api/auth/me` 返回 `403 请求来源不在允许范围内`。后端镜像现默认：

```env
SHIP_REQUEST_MODE=web
SHIP_PUBLIC_ORIGIN=https://dev.zhongshu.tech
```

`web` 模式校验浏览器的 `Origin`，无 `Origin` 的同源 GET 使用 `Referer` 校验；不再要求固定代理 IP，也允许代理将上游 Host 改为内部服务地址。若客户端不发送这两项，请求 Host 必须匹配配置的公开域名。仍要求应用请求头，并拒绝其他站点的来源；登录密码、会话及轮机长/轮机员/管理员权限保持不变。各 API 使用同一校验规则。

容器发布到其他域名时，用环境变量覆盖 `SHIP_PUBLIC_ORIGIN`。环境变量会覆盖镜像默认值，若部署系统中原来填写了 `http://localhost:8080` 等其他地址，应一并改为实际网站来源。Compose 默认仍面向本机 `http://localhost:8080`，公司部署时在其 `.env` 设置实际公开域名。启动日志的 `requestMode` 与 `publicOrigin` 会显示当前生效配置。

直接本地 Node 启动默认使用 `SHIP_REQUEST_MODE=local`，保留本机与指定代理 IP 的校验；`SHIP_TRUSTED_PROXY_IPS` 仅对此模式生效。无需为了公司网站部署修改可信代理 IP 清单。

本地直接运行 Node 时，此参数默认空值；可在环境中设置 `SHIP_CONTEXT_PATH=ship-smart-engine-room` 以验证同样的子路径。前端沿用相对资源路径与 Hash 路由，无需因此重新构建 `dist`。

## 公司服务器启动

服务器需要 Docker Engine、Docker Compose V2。检出包含普通数据库的新提交后即可构建；当前这份数据库不需要 Git LFS 下载。首次拉取后执行：

```sh
git checkout env/dev
cp .env.example .env
```

在 `.env` 中设置实际部署地址，例如 `SHIP_PUBLIC_ORIGIN=https://实际公司域名`，只包含协议、主机和可选端口，不包含子路径。默认子路径为 `ship-smart-engine-room`，对应访问地址 `https://实际公司域名/ship-smart-engine-room/`。

如直接通过服务器内网 IP 和 8080 端口访问，设置 `SHIP_BIND_IP=0.0.0.0`，并把 `SHIP_PUBLIC_ORIGIN` 设为实际的 `http://服务器IP:8080`。默认只绑定宿主机 `127.0.0.1:8080`，供同机公司 Nginx 转发。

```sh
docker compose build
docker compose up -d
docker compose ps
docker compose logs --tail=100 backend frontend
```

默认本机访问地址：`http://localhost:8080/ship-smart-engine-room/`。本次没有访问公司服务器执行以上命令。

## 公司入口 Nginx

Compose 内的前端 Nginx负责静态文件与 API 代理，宿主机已有的公司 Nginx 保留子路径转发至它。下面配置放在公司域名的 `server` 块内：

```nginx
location = /ship-smart-engine-room {
    return 301 /ship-smart-engine-room/;
}
location /ship-smart-engine-room/ {
    # 这里不加结尾 /，保留原始 context-path。
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header Connection "";
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 240s;
    proxy_send_timeout 240s;
    client_max_body_size 12m;
}
```

Compose 前端 Nginx 转发到 Node 时，才去掉子路径前缀。两层均关闭缓冲，保证助手流式输出。建议保留浏览器访问的 Host 便于日志排查；网站模式校验配置的公开来源与浏览器 Origin/Referer，不依赖代理 IP 或内部 Host，也不通过 `X-Forwarded-*` 判断来源可信。

独立网络默认为 `172.30.86.0/24`，前端代理固定为 `172.30.86.2`。如与服务器已有网络冲突，在 `.env` 同时修改 `SHIP_NETWORK_SUBNET` 和 `SHIP_PROXY_IP`。后端不发布宿主机端口。

- 后端支持 `/healthz` 与 `/readyz` 的 GET/HEAD 探针，启动时验证数据及模型配置可读取；探针不访问外部模型。缺失部署数据会在接受流量前报错退出。
