# 轮机长维保建议统一详情修改方案

日期：2026年10月14日  
状态：用户已授权实施；U01／U04主体已完成本地验证，待用户复核；其他待办按本方案边界后续处理  
对应待办：U01、U04；决策表达涉及 U02，助手协作涉及 U03。后两项在本方案中明确契约，实施边界见第十节。

## 一、用户任务与设计目标

主要用户为轮机长。AI 综合一次次设备健康分析及持续跟踪材料，识别某部件可能衰减或已具备维护必要性，提出提前检查或提前维保建议。轮机长审阅建议的真实性、合理性及安排必要性，确认是否安排人员行动，并跟进结果。

详情应优先回答五个问题：

1. 哪个部件出现什么变化，AI 具体建议做什么？
2. 建议由哪些历次分析、观察和现场证据支持，哪些仍不确定？
3. 为什么要比原计划提前，继续原计划有什么考虑？
4. 已有计划、工单及作业条件是否允许这样安排？
5. 轮机长作了什么决定，目前接续到哪里？

以新版的审阅顺序为首页主线，吸收原版的建议演变、已有安排、人员决定与执行回馈，形成一份统一详情。不是把两页全部内容简单拼接，也不是增加第三套独立入口。

## 二、业务对象及边界

| 对象 | 职责 | 与维保建议的关系 |
|---|---|---|
| 设备健康分析记录 | 记录一次分析的范围、证据、判断、限制及时间 | 作为建议来源，不因分析运行就生成建议 |
| 持续跟踪档案 | 对同一变化接续观察、补证和判断更新 | 建议引用相关记录；派工后仍保留跟踪主线 |
| 维保建议档案 | 表达建议措施、理由、适用条件、轮机长决定及后续进展 | 本次统一详情的主体 |
| 行动事件 | 承载人员检查、排查、实际维护及验收 | 由明确行动决定创建或关联，同一问题已有事件不重复建立 |
| 正式计划及船管工单 | 保留正式作业范围、计划及办理记录 | 详情只读展示；在事件内确认选择，不修改原工单 |

证据还不足以支持部件衰减或具体维护措施时，明确为“提前检查建议”。支持具体维护措施时，才表达“提前维保建议”。不能把振动上升、周期临近或靠港方便单独写成已确认衰减。

当前轴承演示有 2.1→3.0 mm/s、周期及靠港信息，尚缺完整现场证据，初始应保持“提前检查”。“机体振动”与“轴承振动”的来源口径须核对；无法核实时标记测点／部位对应关系待确认，不使用机体测点直接证明轴瓦磨损。不补造衰减率、剩余寿命或紧急期限。

## 三、统一页面框架

共用页头：返回、建议标题、设备与部位、建议类型、当前建议状态。时间明确区分建议首次提出和最近判断更新，不以打开页面的时间替代业务时间。

三个页签：**建议概览／依据与评估／决定与进展**。这些名称是本方案建议，待审阅后确定。

左侧承载审阅与业务记录，右侧为该建议自己的助手。设备助手、建议助手、行动事件助手分别保留职责；建议从不同入口打开使用同一会话集合。

全局灰底、白色内容面板、既有金色重点与深色主动作保持。避免多层背景嵌套。桌面利用左右信息分区，横屏 Pad 保持可读并允许上下布局；本轮不增加窄屏手机需求。

### 3.1 建议概览：轮机长默认审阅页

按以下顺序组织，避免默认展开全部长分析：

| 顺序 | 内容 | 展示要求 |
|---|---|---|
| 1 | 建议摘要 | 明确部件、变化、建议措施和为什么现在提出；区分建议检查与建议维护 |
| 2 | 最新判断与边界 | 支持了什么、还不能证明什么、缺什么关键材料 |
| 3 | 关键依据 | 3—4项真正支撑建议的证据，各附比较基准、时间范围及来源；周期进度不作为健康程度 |
| 4 | 相比原计划的必要性 | 原计划是什么、提前能解决什么问题、仍待确认哪些前提 |
| 5 | 已有安排摘要 | 原周期、候选窗口、已有事件／工单，缺失时直接说明，不用预设编号冒充关联 |
| 6 | 当前轮机长决策 | 依据当前建议及证据展示实际需要决定的行动；已安排后显示安排摘要，避免重复派工 |

概览不重复渲染完整证据表、完整任务步骤和完整对话历史。移除正文中的内部页签跳转快链，直接使用顶部页签；关联来源档案、事件和正式安排仍可提供业务入口。

### 3.2 依据与评估：解释建议如何形成

**A. 建议来源链**

先展示来源摘要，再按时间展开相关记录：

- 首次值得关注的变化与建档理由。
- 后续可比分析／观察：与此前相比扩大、持平、收敛或无法判断。
- 关键判断更新：新增哪些证据，使 AI 提出或修订维护建议。
- 已确认现场反馈：反馈来源、时间、核实状态及它支持的判断。
- 本次建议：所引用的证据、措施和仍待确认的条件。

每条区分事实、AI 判断及判断限制；新判断追加记录，不覆盖当时结论。不是每次模型调用都列一条，也不按日重复创建建议。仅展示已有可追溯记录，缺少节点就说明材料不足。U08 中持续关注档案的完整重设计不在本项自动展开。

**B. 关键证据与解释**

保留新版“事实—推断—缺项”的表达，配合指标摘要、已有观测节点、比较参考及现场证据状态。趋势只连接已有有效节点，不插值补造采样点；数据缺失、工况不可比不能被解释为正常。

**C. 提前必要性与可实施性**

| 评估维度 | 需要回答的内容 |
|---|---|
| 提前必要性 | 当前变化与维护措施的关联、继续原计划的考虑、为何建议提前 |
| 证据充分性 | 现有证据支持检查还是具体维护；哪些事实仍未确认 |
| 作业条件 | 实际窗口、停机隔离、人员、备件及许可是否取得确认 |
| 既有安排 | 正式计划／已选工单是否覆盖同一部件及范围，是否需要核对安排重叠 |

展示只读的完整已有安排；桌面证据主区与安排摘要并列，Pad 上下排列。工单选择仍集中在关联事件，不在建议页另建选择器。

### 3.3 决定与进展：看清决定后接续到哪里

分区展示：

1. **轮机长决定**：决定的行动范围、理由、决定人、时间及后续修订。
2. **当前安排**：负责人、任务要求、计划时间、关联事件、所选工单及来源。区别“作出决定”和“已落实安排”。
3. **检查与执行反馈**：原事件的实际记录及来源，不以计划措施代替已执行措施；显示现场执行时间和验收结果。
4. **效果回馈**：已有有效观测及判断；待数据、仍异常等状态如实保留，不预设改善结论。
5. **关键进展记录**：提出／更新建议、人员决定、安排、现场反馈等节点，保持关联，不重复展开另一套现场处理表单。

建议详情主要供轮机长跟进，详细步骤在原事件中办理。实际执行完成、异常解决、效果观察结束、建议关闭和正式工单完成分别表达，不相互推导。建议自动关闭规则仍待讨论。

## 四、决策语义与安排契约（U02）

| 当前情况 | 可供审阅的决定 | 明确边界 |
|---|---|---|
| 证据只支持进一步检查 | 安排检查／暂不采纳本次建议并说明原因 | 不等于批准提前保养或换件 |
| 证据支持具体维护措施 | 安排提前维保／暂不采纳本次建议并说明原因 | 安排不等于已执行，不自动改原计划 |
| 已有同问题行动事件 | 查看／调整原安排；需要新的决定时说明原因 | 不重复创建事件，不退回已完成步骤 |
| 已有实际执行记录 | 回看结果及后续观察 | 不再显示重复发起执行的主动作 |

不采纳仅适用于维保建议，记录原因并保留原计划及档案；不代表恢复正常，不能把它当成关注事项结束。类型范围按 U05，分类落位及具体状态名称另行确认。

负责人、时间与处理要求是行动决定后的安排信息，不代替“同意检查还是维护”的决定。允许同一确认过程完成决定与安排，但确认前明确行动范围，取消时不留下半创建的任务。具体按钮命名和视觉权重在 U02 处理时审阅。

“是否具备维护依据”应来自已确认的业务证据，不仅由事件阶段序号判断。原型可使用明确的场景证据状态，但不得声明已完成真实 AI 评估。

## 五、右侧助手契约（U03）

初始消息用短摘要交代建议、依据限制及当前审阅任务，不再复制整个左侧报告。可提供关于提出理由、补证要求、原计划和当前安排的追问。

- 解释必须引用当前建议的来源材料；尚未取得的记录不能作为事实回答。
- 人员补充可整理为待确认材料；普通聊天和草稿不自动视为已核实事实。
- 左右共用业务草稿与确认方法；从任一侧确认只保存一次，右侧追加回执。
- 业务状态改变不改写旧助手输出；新的依据、决定及安排以新消息接续。
- 切换详情页签不新建会话，切换历史会话不改变左侧业务档案。
- 原事件里的执行记录共享机制继续保留；建议助手不得另造执行已完成记录。

当前没有真实模型及船管执行回传接口。原型中的整理规则、示例消息与接口演示数据明确标注来源，不写成真实能力已上线。

## 六、内容与数据整合

以一份建议档案数据驱动两侧展示，不再让 `issueDossiers.json` 与原维保详情各自给同一建议维护另一套结论。

建议数据契约：

| 数据组 | 最少内容 |
|---|---|
| 身份及来源 | 建议ID、设备ID、部件、提出时间、最近评估时间、来源档案与分析记录引用 |
| 当前建议 | 建议类型、具体措施、依据摘要、判断限制、待确认问题 |
| 来源过程 | 节点ID、业务时间、事实、判断、限制、来源引用；已有有效记录 |
| 评估材料 | 指标／测点及部位、工况、比较基准、观测范围、有效性、现场证据状态 |
| 安排引用 | 原周期计划、关联事件、已有工单及同步来源；缺项如实保留 |
| 人员决定 | 行动范围、理由、决定人及时间、安排记录引用 |
| 执行与效果 | 原事件实际记录与观测引用；不复制独立可变记录 |

整合规则：

- 保留新版事实／推断／缺项的内容，补入原版真实已有的来源节点、工单和进展。
- 概览显示最新有效判断，过程记录保留历史快照。
- 人员决定、指派和不采纳记录需要接入统一展示，不能只读取 `advice.records` 而遗漏 `assignmentRecords`、`ignoredSuggestions`。
- 原型采用已有数据和明确演示夹具，不为补完整链而生成虚构的衰减证据。
- 多个不同来源记录只按明确业务关联整合；同次作业的船管回传去重是 R07／R08 后续事项，本项不冒充已经完成。

## 七、统一入口、返回与会话（U01／U04）

### 7.1 入口

建议规范入口为 `/situation/maintenance/:adviceId`，本期现有建议为 `maintenance`。

工作台、事项总览、设备相关事项、动态记录及助手链接统一指向建议详情。旧 `/situation/issue/maintenance` 兼容到同一详情，保留来源上下文，不再渲染另一套建议正文。`planned` 保留为常规安排只读入口，避免被当作建议ID。

已派发事项列表的“查看进展”可继续进入原事件，符合它的动作含义；回查建议的链接仍回统一建议详情。同一建议入口统一不等于把所有事件入口改成建议页。其他类型的 `CaptainIssueDetail` 本项保持。

### 7.2 返回

保存发起入口、设备、类型与状态筛选、列表滚动位置及已加载范围。返回分别恢复工作台、事项总览、设备相关事项或动态记录，而不是一律返回维保列表。内部进入事件／计划详情后能回到原建议，不改变已有业务状态。

### 7.3 会话

以建议业务ID生成唯一建议智能体标识，如 `maintenance-advice:<adviceId>`，不由路由名称、发起入口或页签生成。

旧 `issue:maintenance` 和 `maintenance-advice:1` 的会话归属需明确映射到同一建议：保留每条会话的消息、时间、草稿和选择位置，不按标题盲目去重，不强行把两条独立会话拼成一条。若同一消息有稳定ID，可按ID避免重复。初始化只生成一次开场，不因切换入口重复加入假用户提问。

当前会话为内存原型；仅处理当前运行态的归属兼容，不声称刷新持久化或后端会话迁移已实现。事件智能体与常规计划核对助手仍独立。

## 八、视觉及交互细节

- 概览围绕一条清晰的审阅主线，不默认展开全部分析。
- 关键指标、来源、判断限制有明确层级；状态和数字不靠颜色单独表达。
- 证据用指标摘要、解释表、有限观测节点及可展开来源记录，减少纯文字长段和桌面大面积无意义留白。
- 使用顶部页签切换内容，不恢复此前已移除的正文内部页签跳转按钮。
- 决策区只有当前有效的行动，不叠加两套“采纳／指派／执行”操作栏。
- 待确认表单具备必填与错误提示；取消、重复提交及状态变化后过期请求有明确处理。
- 遵循现有PC1080p、2K及横屏Pad适配目标。助手与左侧各自滚动，内容不被固定操作区遮挡。

## 九、内容验收故事

| 场景 | 必须看到 | 不能出现 |
|---|---|---|
| 当前证据仅支持检查 | 来源链、缺项、原计划、明确的检查建议 | 把振动上升直接写成轴瓦衰减确诊或已同意换件 |
| 已取得充分检查依据 | 判断如何更新、具体措施及待安排条件 | 只因页签／阶段切换就改写历史输出 |
| 轮机长安排检查 | 明确行动范围、人员要求、同问题事件 | 自动完成工单或重复建立任务 |
| 暂不采纳 | 原因、决定时间、保留的档案与原计划 | 等同设备正常、删除过程或自动取消已有事件 |
| 实际执行已记录 | 实际措施、执行时间、验收及来源引用 | 以预置计划文本冒充执行事实 |
| 监测缺失或不可比 | 数据限制、等待补证 | 默认恢复正常或编造改善曲线 |
| 多入口回查 | 同一档案与会话集合、准确返回 | 两套详情、丢失决定或历史会话 |

## 十、实施拆分与验收边界

建议按以下顺序处理，避免一次性扩展全部业务：

1. **U01／U04主项**：统一建议详情、内容适配层、来源与进展展示、全部建议入口、返回及会话归属；吸收新版分析表达。现有可用业务动作保持接续，未统一前不得出现两套相互冲突的决定。
2. **U02／U05相关部分**：逐项审阅决策动作、指派契约和不采纳状态后实施；不把本方案草案视为这些细节已确认。
3. **U03**：逐项确认补充字段、待确认卡片及左右共享范围，再实施建议助手协作。
4. **U07／U08及R07／R08余项**：验收流转、持续关注、真实回传与履历去重另行处理；本项只提供引用和状态表达，不偷偷改这些规则。

技术验收需覆盖：各入口一致、旧链接兼容、返回状态恢复、业务ID对应、判断与历史快照分离、已有决定及指派可见、会话切换和草稿保留、事件／工单职责隔离、PC1080p／2K和Pad布局。自动测试只验证业务契约与回归风险；浏览器实际走通关键故事，构建通过后报告仍未接入的真实能力。
