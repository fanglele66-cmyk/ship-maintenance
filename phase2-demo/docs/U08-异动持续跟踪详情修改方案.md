# U08：异动持续跟踪详情修改方案

编制日期：2026年10月14日  
状态：用户已授权实施，原型已修改并完成相关验证，待用户复核。方案正文保留，实施情况及限制见第10节。

## 1. 修改目标与已确认依据

当前异动详情沿用“初判、建议、证据、采纳并指派”的一次性决策结构，未充分呈现同一变化的持续发展。轮机长仅凭当前读数难以判断问题，需要同时了解首次关注理由、历次变化和本次为何需要人员配合。

本次改为持续跟踪档案：默认展示性能衰减或相对偏离的趋势，串联关键发现与当时判断；需要人工介入时，轮机长审阅并派工，后续核实、检查、执行和确认由待办承载，反馈回到原档案。

已确认的要求：

- 异动可能只是劣化的前期征兆，不直接表达为已确认故障。
- 此前跟踪情况与当前判断一起呈现，不把历史仅放在下方回查。
- 独立详情采用“跟踪概览／分析与证据”两个页签。
- 默认顺序为“变化趋势与当前判断 → 跟踪过程 → 当前跟踪与人员行动”。
- 趋势围绕具体劣化指标与可比参考表达，结合关键节点说明变化；不生成统一健康分数或虚构连续曲线。
- 3号缸默认展示缸间排温相对差，绝对排温作为可切换辅助图。
- 派工后继续跟踪；分别表达变化情况与任务进展；待办反馈形成新节点，后续判断保留更新依据。
- 现场核实集中在待办，不在异动详情再建执行表单；U03 助手业务接入放到详情方案确定后处理。

以下路由选择、展示字段、实现拆分和验收场景是为落实上述要求提出的具体方案，不视为已经实施。特别是派工后入口和历史档案召回方式，需随本方案评审。

## 3. 页面内容与交互

### 3.1 共用头部

展示返回入口、档案名称、设备与部位、首次建立关注时间、最近有效更新、跟踪阶段及人员任务进展。

区分最早观测时间、建立关注时间、有效分析时间和任务反馈时间。任务或留言更新不得伪装成新一次有效分析。缺少确切时间时沿用来源的时段标签，不补造日期。

跟踪阶段可表达系统跟踪、需人员核实、关联检查中、处理后观察或已结束；同时展示任务未派发、已派工、进行中或反馈已提交等信息。具体映射从现有业务事实推导，不新增第二套可独立修改的状态。

需要人员时，页头附近显示简短提示，例如“偏差继续扩大，建议派工核实现场读数与工况”。详细理由和操作集中在下方行动区。

### 3.2 跟踪概览：变化趋势与当前判断

- 桌面以趋势图为主，邻近展示当前解释；较窄窗口上下排列，保证单位、参考、节点标签可读。
- 图表支持指标切换，说明比较对象、工况和有效观察范围。
- 3号缸默认“与其余缸平均排温的差值”，辅助“3号缸绝对排温”；空压机默认“可比加载周期耗时”，辅助供气压力、排气温度等已有记录。
- 时间点具有可靠时间值时按实际间隔绘制；仅有班次或轮次标签时按顺序展示，并明确这是节点序列，不冒充连续时间采样。
- 使用观测折线或节点图，不进行缺失插值和平滑拟合。缺失点断开；不可比样本标注并排除发展判断。单点仅展示快照，不能画衰减趋势。
- 参考区间只有来源及适用对象明确时才显示。不得把展示范围变成故障阈值；排温相对差与绝对排温报警阈值不得混用。
- 最新判断说明相对起始和最近前次的变化、近期方向、证据限制及本次行动理由。多个节点能说明偏离发展，不自动支持预测故障时间或计算可靠劣化速度。
- 关键节点标注建档、请求配合、反馈和实际处理。点击有对应记录的节点，定位并展开跟踪过程中的记录；纯观测点只显示数据及比较信息。
- 实际处理后保留处理前历史，并按已有执行时间标出分界；可增加处理后指标查看，不把整个档案替换成只有效果观察的图。

### 3.3 跟踪概览：跟踪过程

按先后顺序展示关键节点，默认摘要可见，详细依据展开查看。可对长记录提供“展开更早记录”，但首次建档理由与关键发展不能全部隐藏。

| 信息 | 展示要求 |
|---|---|
| 时间与来源 | 观察范围或确认时间，系统分析、人员确认、待办反馈等来源 |
| 本次发现 | 新增表现及相对前次的差异，链接对应观测或反馈 |
| 当时判断 | 当时为什么建档、继续跟踪或调整解释；保留限制 |
| 当时安排 | 继续观察什么，或需要谁核实什么 |
| 来源关联 | 返回原待办阶段、反馈或证据；资料不完整时明确说明 |

节点包括建档、重要观察更新、请求人员配合、派工、人员确认反馈、判断更新、实际处理、效果观察和结束。按已有业务事实形成，不为每次算法调用、普通聊天或草稿新增节点。

“反馈已提交”与“判断已更新”分别记录。反馈回来而尚无更新分析时，显示“反馈已留存，后续判断待更新”，不自动宣称风险解除。旧判断不被覆盖；同一确认记录反复打开只出现一次。

### 3.4 跟踪概览：当前跟踪与人员行动

| 情形 | 内容 | 操作 |
|---|---|---|
| 暂无人工要求 | 继续观察的指标、参考及介入理由 | 查看证据；不默认显示派工按钮 |
| 需要人工且尚未派工 | 新证据、介入理由、核实或检查范围、需反馈的信息 | “安排现场核实”或“安排进一步检查”，展开负责人及任务安排 |
| 已有待办 | 负责人、当前阶段、任务范围、最近确认反馈 | 进入关联待办；不重复创建任务 |
| 反馈已提交 | 本次反馈摘要、分析更新状态、系统后续安排 | 查看原反馈和待办；需要后续行动时沿同一问题接续 |
| 已实际处理 | 已确认措施及时间、处理后可比观察、限制 | 回看执行记录与观察依据 |
| 已结束 | 原变化恢复或已解决的依据、范围、结束时间 | 回看过程与来源；无常驻派工操作 |

派工表单复用现有负责人、协作人员、任务类型、计划和范围。当前3号缸范围限定现场核实；明确核对时间、现场排温与系统读数、运行工况和现场现象。不能因指派自动认定故障或同意维修。

异动不显示“忽略／不采纳建议”；这是已确认 U05 对异动类型的适用要求。暂不能派工的表达和记录方式若需增加，另行细化，不直接沿用维保“不采纳”机制。

派工成功沿用已确认的返回发起清单逻辑。任务的核实填写、执行及确认集中在待办；详情不增加另一份执行表单。

### 3.5 分析与证据

按“比较范围与工况 → 详细分析 → 参考及来源 → 人员反馈与实际措施 → 数据限制及结束依据”组织。

详细分析区分观测事实、候选解释和缺少的证据。来源注明为演示资料、系统观测、人员确认或原待办成果；未取得的手册、采样覆盖率或真实接口记录不作为已核验依据。

保留旧档案中已有反馈及来源，统一标明其产生方式。历史直接提交的核实记录可回看，新版人工流程不再生成第二套详情核实表单。

## 4. 入口统一方案

建议以 `/situation/attention/:id` 为异动档案的统一地址，复用并扩展原档案组件；空压机接入同一框架。`/situation/issue/drift` 与 `/situation/issue/air-delivery` 兼容跳转到对应档案，保留来源查询参数。

| 入口 | 建议行为 |
|---|---|
| 工作台、事项总览的未派工异动 | 打开同一档案，审阅后派工 |
| 工作台、事项总览的已派工“查看进展” | 保留直达原待办，并在待办提供来源档案入口 |
| 设备相关事项 | 异动标题提供档案回查；明确的“查看待办进展”进入原待办 |
| 动态记录中的异动记录 | 始终回到档案，不因已经派工跳到另一套分析详情 |
| 原关注链接及旧新详情地址 | 解析同一档案标识，不产生第二份记录 |
| 待办的来源材料 | 可回看同一档案；返回恢复原待办及当前阶段 |

返回保留发起位置、设备、类型、状态筛选和列表滚动。此项是档案入口接续，设备四主页签保持；不扩展到 U06 全部分类重做。

维保路由本轮已由其他工作调整，U08 导航实现应使用限定为异动的分流逻辑，不重写维保分支。来源事件、工单和维保档案仍保持各自职责。

## 5. 数据接续与复用

建立统一的异动档案展示适配，读取既有示例和待办状态。建议输出以下信息组：

| 信息组 | 核心内容 |
|---|---|
| 档案身份 | 稳定标识、设备、部位、关注理由、最早观测及建档时间 |
| 观测序列 | 指标、单位、点标识、时间或时段、数值、可比条件、参考来源、缺失原因 |
| 判断记录 | 稳定标识、证据范围、当时判断及限制、当时跟踪或人工要求 |
| 关联行动 | 原待办标识、负责人、范围、当前进展、已确认成果引用 |
| 跟踪节点 | 节点类型、发生时间、来源记录标识、摘要、详细证据引用 |
| 最新展示 | 最近有效观测与判断、任务进展；不由任务状态代替变化判断 |
| 结束信息 | 原结束依据、覆盖范围和来源；与事件关闭分开 |

从 `assignmentRecords`、已确认 `feedbackRecord`、`executionRecords` 及有效观察记录汇集成果；阶段序号、预置任务文字、未确认草稿或普通聊天不能作为已执行证据。

用“来源待办＋来源记录标识＋节点类型”保证同次成果只出现一次。优先读取原成果并建立引用，不维护第二份可编辑执行结果。对现有缺少稳定记录标识的成果，实施时补齐标识，不用名称或渲染顺序做业务去重。

首次建档时间不随新反馈变化。实际执行时间与提交时间分别保留；无实际执行时间不画伪造处理分界。图表点和判断节点分别关联，不能一律把观测点解释成新一次判断。

现有适配中的固定调度文字、统一工况、采样间隔、覆盖率和跨设备参考须逐项核对。没有来源支持时显示未取得，不把主机参考套用于空压机。真实调度频率及自动分析不在本次建设范围。

### 6.1 3号缸：偏差扩大，需要现场核实

| 演示观测 | 排温相对差 | 绝对排温 |
|---|---:|---:|
| 10月9日08:00 | 5°C | 425°C |
| 10月10日08:00 | 8°C | 428°C |
| 10月11日08:00 | 9°C | 430°C |
| 10月12日08:00 | 10°C | 432°C |

来源为原 `r02Stories.js` 的演示观测。建档判断为10月10日，请求现场核实判断为10月12日；10月11日只有观测点，不补写一次判断。新详情当前仅有两个点，完整四点需接入后再验收。

当前说明草案：

> 已有可比观测中，3号缸相对其余缸的排温偏差逐步扩大。当前是值得核实的局部变化，尚不足以确认故障或具体原因。建议安排人员比对现场与系统读数，记录对应工况和现场表现，帮助判断实际变化、测量偏差及工况影响。

派工后显示“偏差扩大，判断待核实｜现场核实已派工”，不是“故障已确认”。核实反馈回到档案后，新增确认记录；是否形成新的判断，应有对应分析结果及依据。

### 6.2 空压机：加载时间延长

采用已有三个班次观测：95、112、128秒；辅助供气压力0.82 MPa及排气温度已有记录。图注明同一储气压力区间、相近用气条件，不把这些节点作为效率百分比、磨损程度或剩余寿命。

旧组件保留10月11日至13日的过程文字，其他配置使用班次标签；实施前核对对应关系和来源，不自动把日期与班次拼成新的精确时间序列。未找到可靠对应时使用已有班次口径。

### 6.3 无需人工及自然结束

4号缸用现有反复偏差、尚未扩大示例，展示为何持续跟踪及当前无需派工；2号缸用原自然恢复示例，展示未维修也可在证据支持下结束，保留过程和结束依据。

各示例明确演示属性。代码中的覆盖率和观察阈值不视为真实参数验收；来源不足的精确指标删去或改为缺失说明。

## 7. 实施拆分及共享文件协调

1. 核对异动档案标识与统一适配，分离观测、判断和人员成果，保留旧资料。

3. 兼容新旧路由，补齐动态记录和待办的档案回查；保留发起位置恢复。
4. 复用派工表单，限定为核实或检查范围；接入待办已确认成果展示及去重，不改 U07 未定流转。
5. 核对2号、4号档案回查、结束表达及缺失数据分支，完成专项验收。

主要文件：`AttentionDossier.vue`、`attentionDossier.js`、`AirAttentionDetail.vue`、异动数据配置与导航辅助。涉及 `SituationView.vue`、`DeviceSituation.vue`、`DeviceIssueBrowser.vue`、事项列表、路由、待办视图和 store 的改动需逐处协调。

## 9. 本方案评审重点

- 是否接受以原异动档案地址为统一入口，并保留已派工“查看进展”直达待办、同时补齐档案回查。
- 是否接受设备相关事项的档案入口与待办进展入口分开表达，以及2号、4号先通过记录回查而不全部进入待决策清单。
- 派工范围、节点字段及图表样式是否满足轮机长理解劣化过程的需要。
- U07 未定验收流转与 U03 助手接入作为后续工作，当前只接续真实已确认成果，不以新页面提前改变规则。

上述重点用于集中评审具体落地方式，不重新讨论已确认的持续跟踪定位及人工流程。
