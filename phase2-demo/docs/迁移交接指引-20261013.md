# 船端迁移交接指引（2026-10-13）

## 1. 当前定位与协作规则

这是船端二期原型，不是岸端。态势中心是轮机长工作台，负责全船判断、查看事项和决策派发；待办中心是负责人的任务推进工作台。所有事项起源于态势，采纳并选择负责人后才形成待办。

必须遵守：先讨论问题 → 记录已确认结论 → 写修改方案 → 用户确认 → 开发 → 技术验收 → 用户验收。不得分析完随手扩展修改；不明确的版本、定义、范围先问。每个待办保留方案、检查和发布记录。新发现问题先记录，不夹带进当前实现。当前SIT-04已经获执行授权，不用重复确认整套方案。

## 3. 已完成的SIT-01至03（保持，不重新设计）

详见docs/优化待办总表.md及对应方案。当前状态是已实现并技术验收，等待用户继续体验验收，不能擅自写成用户已验收。

- 报警 > 预警 > 异动 > 维保；同类型设备影响力：主机 > 舵机 > 空压机 > 锅炉。
- 工作台按类型后设备排序；总览先待决策后已派发，再按类型/设备排序。
- 报警/预警红色，异动/维保橙色；信号灯按活动事项最高类型判断，与是否派发无关；无活动事项绿色。
- 工作台待决策/已派发两页签、设备筛选、最多5条；列表独立滚动，固定底部“查看全部事项”，无计数；少量内容模块收缩。
- 总览默认全部设备/全部类型/全部状态，三个标准选择器，进入不继承外层条件；每批10条，点击加载更多。
- 行动作：待决策查看分析，已派发查看进展；外层状态页签内不重复标状态，总览混合列表显示状态。
- 新派发成功返回发起清单并保留筛选、批数、滚动位置，不自动跳待办。查看进展才主动进入待办。已有任务调整指派不跳转。
- 仅未闭环事项进入工作台；人工处理完成、效果观察归档都不等于真实事件闭环。实际闭环判定由eventStatus提供，不用旧closed阶段自动推断。
- 设备层四主签：健康概览、传感器数据、动态记录、相关事项；相关事项下四类。具体待办阶段及维修验证不能随意简化或重构。

## 4. 正在进行的SIT-04（交接后优先继续）

用户授权：优化从事项处置行进入、派发前的“事项详情页”，明确不是待办阶段卡。暂定三页签：事项概览 / 研判分析 / 证据资料。

- 事项概览：初判结论与建议先行；关键依据摘要；推理摘要可选展开；中间快链到另两页签；下一步选择/标准指派放首签最下方。
- 研判分析：观察事实、推断、候选解释与未确认问题分层，不堆纯文字；返回概览恢复位置。
- 证据资料：数据快照、可核对的证据链、已有观测节点/趋势、来源/计划、人员反馈与决定。无数据则明确缺项，不补造连续趋势、数值、精确时间、置信度和说明书来源。
- 四类共框架、用JSON填充不同产物：报警=越限及关联；预警=多指标联动；异动=可比偏离与发展；维保=原计划与提前依据。
