# 维保详情配置与组件复用

## 维护入口

- src/page-content/maintenance.json：静态章节、页签、关联入口。
- src/mock/phase2SituationContent.js：根据当前状态生成结论和动态段落。
- src/mock/maintenanceDossier.js：组合报告、状态、元信息与可见动作。
- src/components/MaintenanceDossier.vue：维保统一展示。
- src/components/SituationReport.vue：共享报告骨架。
- src/views/DeviceSituation.vue：处理明确的导航动作。

## 内容与状态边界

普通段落填写字符串；动态段落使用 {"source":"plannedCoverage"} 这样的显式引用。引用键必须在内容适配器中存在。不要在 JSON 中编写表达式、调用函数或修改 store。

现有动态来源：plannedCoverage、plannedExecution、checkEvidence、executionHandoff、effectEvidence。增加来源时应同时补充适配与状态检查。

动作配置维护 id、label、when；when 只支持适配器声明的条件。新动作必须在页面处理函数中显式实现，配置一个新名字不会自动产生操作。

## 扩展原则

同类维保材料优先使用现有组件和模型；新增材料维护独立稳定标识、章节和事实来源。不要将某条模拟故事写进通用组件。常规计划和提前建议共用部件依据，但不共用是否采纳的状态。

验证入口：node --test tests/maintenance-dossier.test.mjs；完整相关检查可运行 tests 目录现有六个测试文件。发布前运行生产构建，并检查概览、证据、记录以及关联待办和观察入口。
