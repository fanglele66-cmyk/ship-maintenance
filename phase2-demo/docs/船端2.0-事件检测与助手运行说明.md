# 船端 2.0：事件检测、助手交互与效果观察

本次把新产生的人工上报、周期检测事件及其任务、报告和会话接入本地后端。既有固定案例继续保留原来的浏览器演示行为。实现入口是 `server/workflow-service.mjs`；前端仍使用现有事件和任务页面。

## 检测与 Skill

从 `D:\zstech\ship-changhangbiyu\.claude\skills` 复制了 `ship-anomaly-detection` 和 `ship-manual-anomaly-analysis` 的源文件、引擎、模型、配置及参考资料；原 Skill 正文保存在各自 `references/original-skill.md`。本项目的顶层 `SKILL.md` 改为船端 2.0 契约。

新增 `ship-event-assistant`、`ship-task-assistant`、`ship-effect-observation`。后端按照当前业务入口选择 Skill，读取其正文作为模型指令，并在调用前后校验身份、输入与输出。检测算法由 Python 实际执行；这不是依赖 Claude Code 自主发现 Skill 的方式，也没有启动原船端的四产物发布器。

周期检测在每次服务启动时运行一次，随后以本次启动时刻为基准每小时运行，读取最近六小时数据。调度每 15 秒检查一次，正在执行时不重入；失败后五分钟重试。关机期间不补跑每一个小时，重启直接检测当前窗口。健康研判使用独立调度器，保留原先的启动即运行与每小时更新规则。

周期信号只有在检测器标记 `confirmed` 后才进入事件分析。这里表示检测信号成立，不表示设备故障已经确认。同一设备、通道、类型及测点组合的未闭环事件更新检测证据，不重复建卡、派工或覆盖人工记录。第一责任人统一为轮机长。没有有效检测信号时保存本轮结果，不制造事件。

人工上报按每次提交的 `requestId` 隔离。主机使用真实测点目录，从数据库只读查询选定窗口，并在该事件目录运行独立检测，再由人工上报 Skill 分析描述与证据。重复提交同编号同内容返回原事件，不同内容占用同编号会被拒绝。辅机允许上报，但当前没有对应数据库采样，分析必须如实保留待核实项，不能拿主机数据替代。

## 事件、任务与会话

新事件以 `workflow.sqlite` 为持久化事实来源，同时导出 JSON 文件供检查和页面使用。每次更新带版本号；服务端拒绝陈旧版本覆盖。前端在调用助手和退出登录前先同步，普通编辑自动保存。刷新会重新载入后端事件；同步失败显示提示，保留本地编辑供核对。

轮机长负责决策、方案编辑及派发；轮机员只看到本人参与或被派发的事件，并只能回交自己的任务和报告。后端根据登录会话校验身份，不信任提示词内的角色。管理员删除卡片沿用账号库中的删除记录，后台检测、观察和重新载入都会尊重该记录；历史文件保留供追溯。

事件助手可以解释当前事件和报告，生成、修改待派的排查、维修、复查方案。修改按步骤操作契约校验，不能直接改已派任务、原始上报或历史执行事实。由轮机长确认后才产生执行任务。

任务助手保留欢迎语，针对当前步骤收集现场信息。服务端从已保存会话计算追问轮数，最多两轮补充追问，之后给出可采用的备注草稿；模型仍追问时，服务端将已有用户事实整理成草稿，缺少的内容保留待确认。使用者选择“采用到本步骤”后写入左侧备注；选择“继续修改”继续调整草稿。助手不代填检查结果、不代替用户提交报告。

报告先保存检查选项、原始备注及本轮提交快照，再请求模型分析并更新同一报告。失败保留原始提交，允许重试，不伪装成分析成功。

隐藏上下文通过 `<yincang>` 包含事件编号、名称、阶段及身份等关联信息。用户正常输入，界面不显示自动加入的上下文；模型输出中的隐藏标签被过滤。标签只用于提示词组织，访问权限由后端实现。

## 效果观察

轮机长选择观察结束时间并确认后，观察计划和截止时间保存到事件。关联范围为所选系统的全部测点、原事件明确选中的测点，以及主机转速、燃油指令。不是只观察人工最初选中的单个点。

到期后由后端汇总从观察开始到截止时间的实际采样，统计所有有效点的数量、均值、范围、末值、最大间隔与覆盖情况，调用效果观察 Skill 生成报告并交轮机长决策。统计使用完整采样，图形展示降采样至约 120 点。浏览器关闭或退出登录不影响到期执行；服务停止期间到期的任务在下次启动时补跑。失败五分钟后重试，取消或已闭环的观察不会在模型返回后发布过期报告。

每个观察阶段最多生成一份观察报告。到期不等于维修有效，也不自动闭环；停机时不把参数平稳当成运行效果验证。本次新事件以计划时间触发，旧固定案例原有的提前介入演示规则继续留在其演示流程中。
