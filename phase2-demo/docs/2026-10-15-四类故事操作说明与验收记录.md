1. 当前主故事收束为冷却报警、3号缸预警、2号辅机健康核实、连杆轴承提前维保四条。主机和三台辅机可分别查看，辅机聚合页增加标准选择器。

3. 预警先核实读数与工况，再进入原因排查；不成立需要人员记录依据后结束。结束核实时不把未发生的排查和维修阶段标成已完成。
4. 长期健康跟踪保留首次、重复和持续变化、现场核实与后续节点。本次任务可结束，健康记录继续。后续持续变化且测量依据成立时关联生成提前维保建议。
5. 提前维保分别记录必要性与条件。不提前处理可结束评估，原计划仍保留；具备依据但缺少条件则留待安排。
6. 实际执行、验收、可比数据、最终闭环分别处理。原异常未解决返回同一事件；缺数据有补充表单；观察稳定后由人员确认闭环；复现保留上一轮记录再排查。
7. 不把仅核实完成生成成实际维护。维护记录来自人员提交的实际作业；责任人保留在任务级，内部阶段没有新增负责人选择。
8. 三页签、阶段卡、InquiryMessage、FormSelect、TaskAssignment 和现有助手框架继续复用。业务内容来自统一配置，动态处置修改任务实例副本，不修改共享原始样例。

## 2. 建议演示顺序

### 2.1 轮机长从态势派发

进入态势中心，先读AI船舶态势分析；主机浮标进入设备健康概览。相关事项可按类型与待决策、已派发、已结束查看。

打开工作台或设备中的事项，三个页签仍为：

- 事项概览：结论、建议、快照摘要、可展开分析、下一步选择。
- 研判分析：事实、解释与缺项，候选方向及需核实内容。
- 证据资料：发生时快照、已有节点、计划与人员反馈。实时刷新不覆盖发生时证据。

点击“采纳建议并指派”，默认显示负责人，补充安排可选展开。选择负责人后确认派发，返回发起的态势列表，继续下一项决定。

派发后再通过左侧待办中心进入负责人视角。不要刷新，否则本轮已操作数据会重置。

### 2.2 报警：只发现阀异常，不能仍让用户清洗滤器

入口：态势中心 → 主机冷却水温报警排查 → 指派 → 待办中心对应卡。

1. 看事件概览、数据观测及候选原因，进入排查。
2. 准备页确认后进入步骤。第一项滤器选择“未见异常”，补充现场读数或检查记录。
3. 第二项温控阀选择“发现异常”，记录实际表现，提交。
4. 进入维修，核对准备、备件、步骤及验收已变为温控阀相关内容，没有虚构滤器清洗。
5. 完成适用的作业步骤，在验收页填写实际措施、实际时间与复测结果；分别选择作业完成、原异常验收通过、可比数据情况。
6. 处理完成后进入设备效果观察。查看后续可比节点，达到窗口后点击人工确认闭环。

再次刷新可体验：仅滤器异常；两项均异常；都未见异常；无法确认。后两者保存反馈，并明确给出继续核实／记录线索入口，不要求改选“正确答案”。

两项均异常时维修有四个对应作业步骤，并保留两组验收。作业完成但原异常仍存在时，验收选“原异常仍存在，继续排查”，返回原事件排查，前轮措施与反馈保留。

### 2.3 预警：3号缸排温先核实，再查原因

入口：态势中心 → 主机3号缸排温预警现场核实 → 指派 → 待办。

1. 查看三个可比窗口的排温、相对差和波动幅度，尚不能据此指定故障部件。
2. 现场核实分别记录读数一致性、工况是否可比及能否解释偏离；异响可写备注，不要求一定存在异响才能推进。
3. 选择“现场与系统一致”“工况可比，偏离仍存在”，进入异常研判，再进入原因排查。
4. 原因排查中分别反馈喷油器、排气相关实际发现。只有第二项异常时对应排气相关处置，不自动安排喷油器维修。
5. 后续沿实际措施、验收与观察继续，保留预警起源。

另一条结局：核实提示工况变化可解释原比较，点击“确认本次预警不成立”，写实际依据后保存。本次核实结束，原材料可回查，不显示未执行的维修为已完成。

### 2.4 异动：人工任务结束，健康链继续

入口：辅机浮标 → 辅机选择器切换2号辅机 → 相关事项 → 排温趋势现场核实。

1. 事项中能看首次、后续、最新三个节点，相对本机参考差+4、+6、+9°C及相应判断变化。
2. 采纳并指派后，负责人核对现场与系统读数，并记录运行背景和现象；本次不要求拆机。
3. 提交后选择“结束本次核实，继续跟踪”，写本次结果与限制。人工待办结束，记录中仍可看原节点与现场反馈。
4. 点击“查看后续可比节点”：第一个节点偏离未扩大，继续记录；第二个节点继续发展，结合原计划提出新的提前评估建议。
5. 若之前现场与系统读数一致，出现“查看本跟踪形成的维保建议”，打开后能回查同一健康记录、现场信息与原季度计划。新建议先待决策，没有自动安排换件。
6. 若现场读数不一致，后续节点仍保留，但暂不生成该提前建议，先核对测量可信度。

1号辅机保留早期轻微偏离记录，没有人工请求；3号辅机没有待决策事项，也有设备概览和传感器资料。

### 2.5 维保：不提前与正常计划不冲突

入口：主机连杆轴承提前维保评估 → 指派 → 待办。

分开看原计划1860／2000 h、振动已有节点和靠港窗口。计划进度不代表剩余寿命。

- 不提前：选择“暂无提前处理必要”，记录检查与条件。提交后点击“不提前处理，保留原计划”，填写依据，本次评估结束。
- 待安排：选择“有提前处理依据”“条件暂不具备”，保留待安排和具体缺项，补足后继续，不虚构已执行。
- 提前执行：选择“有提前处理依据”“条件具备”，接续保养或换件。实际措施按人员确认范围填写，不预填必须换件。

执行表单中的“本次维保验收结果”与报警的“原异常验收结果”分别命名，复用同一标准表单。缺少可比数据时可在设备观察页补充实际测量与工况，未补充前不出改善结论。

### 2.6 观察复现与历史查询

在效果观察中使用“补充观察中的现场情况”，选择原异常复现并记录实际现象与时间；随后确认返回原事件重新排查。前轮观察、执行和反馈继续保留，不复制另一条无关联任务。

主机相关事项选择“已结束”，可看两份预置历史材料：预警不成立、前次提前建议未采纳。新产生的决定、闭环与实际维护可从设备动态继续回查。

## 5. 本轮交付边界

本轮为前端原型，反馈解释和后续节点使用可追溯的场景配置。未接入真实诊断模型、船舶告警、设备说明书或工单执行接口，不将这些能力宣称为本轮已实现。

后续若调整数值、测点、人员或计划，优先改统一配置，核对发生时快照与后续观测分界；修改共享流转时需重新验证四条故事及负向分支。
