# 固定账号与时序数据部署

更新日期：2026-11-12。

本次将当前四个账号的初始化数据纳入代码，并将船舶时序数据库从运行目录中独立导出。新服务器不需要手动迁移账号数据库，即可继续使用现有账号和密码。

## 1. 账号随代码初始化

`data/accounts-seed.json` 已按用户授权提交到代码仓库。它来自当前 `accounts.sqlite`，仅包含账号、角色、姓名、角色名称和 scrypt 密码校验值（salt/hash）；没有明文密码、登录会话、锁定状态或事件删除记录。

| 账号 | 身份 | 密码 |
| --- | --- | --- |
| `chief` | 轮机长 | 继续使用当前密码 |
| `engineer1` | 大管轮 | 继续使用当前密码 |
| `engineer2` | 二管轮 | 继续使用当前密码 |
| `admin` | 超级管理员 | 继续使用当前密码 |

首次启动在 `.local-data/accounts.sqlite` 创建缺失账号，直接导入这些校验值，不再随机生成密码。重复启动、拉取代码和重新构建不会覆盖已有账号；即使运行数据库内的密码后来发生变化，也以运行数据库为准。

已有四个账号时无需再次读取初始化文件。全新部署若缺少或损坏初始化文件，会明确报错，不会悄悄生成另一组密码。`accounts-initial.json` 是旧版本生成的明文提示文件，新部署不需要上传它，也不会根据它导入账号。

账号校验值仅由后端读取。Vite 禁止直接访问此文件，构建检查与实测确认它未进入 `dist` 的页面或 JS 资源。

## 2. 时序数据库单独上传

本机已准备好的目录：

```text
D:\zstech\fang-intelligent-engine-room\ship-maintenance\phase2-demo\deployment-data\telemetry\
  ship-continuous-24h.db
  manifest.json
  receipt.json
  README.md
```

| 文件 | 用途 |
| --- | --- |
| `ship-continuous-24h.db` | 独立实体数据库文件，976,711,680 字节，非快捷方式、符号链接或硬链接 |
| `manifest.json` | 数据库文件名、时间覆盖及处理元信息 |
| `receipt.json` | 数据库与清单校验和、记录数、覆盖时间 |

导出的数据库包含 1,682,921 条传感器记录，覆盖 `2026-06-11 16:51:23` 至 `2027-01-31 10:35:23`，北京时间。数据库 SHA-256：

```text
4f46ed9a2f59f4ebfc86c79a3e0eb10a060722fc075c67650e2c5423456dbb5c
```

将上述三个数据文件手动上传到服务器同样的 `phase2-demo/deployment-data/telemetry/` 即可。Git 只提交该目录的说明与忽略规则，**不包含约 1 GB 的数据库、清单或校验回执**。

也可以放到服务器独立数据盘，例如：

```sh
export SHIP_TELEMETRY_DIR=/srv/ship-data/telemetry
export SHIP_DATA_DIR=/srv/ship-runtime
```

`SHIP_TELEMETRY_DIR` 是数据库与 `manifest.json` 所在目录；`SHIP_DATA_DIR` 是账号、事件、会话、报告与定时产物的可写持久目录，两者分开。默认不配置环境变量时分别为应用下的 `deployment-data/telemetry` 和 `.local-data`。

Node 取数、健康分析、异常检测、人工上报与效果观察取数都已统一支持该路径；异动跟踪的手动分析入口也支持独立数据路径，仍未注册任何新定时任务。三个 Python 入口可显式传入 `--telemetry-dir`。

原 `.local-data` 中的数据库和清单未删除，作为旧版兼容和核对副本保留。默认优先使用新的独立目录；如果旧安装尚未上传独立数据包，仍支持原路径。明确设置了 `SHIP_TELEMETRY_DIR` 时以该目录为准，配置错误不会静默回退到旧数据库。

这份数据的时间覆盖范围有限。超出覆盖期时应更新数据包；读取逻辑仍只取当前时刻及之前的数据。

## 3. 公司服务器首次部署

1. 拉取代码，包括 `data/accounts-seed.json`。
2. 手动上传时序数据目录中的三个文件，并用 `receipt.json` 核对文件大小和 SHA-256。
3. 安装 Node 24、Python 及项目依赖，完成 `npm run build`。
4. 配置独立可用的 `.local-ai/config.json`；公司服务器不能直接使用本机 CC Switch 引用。本次没有修改或提交模型密钥。
5. 按需设置上面的两个数据目录环境变量，以及部署说明中的 `SHIP_PUBLIC_ORIGIN`。
6. 在 `phase2-demo` 执行 `npm start`。运行目录会自动创建，用原四个账号及原密码登录。

后续更新代码保留运行目录；已有事件、任务与报告不作为本次初始化数据。如果需要迁移本机历史业务记录，另行迁移原 `workflow.sqlite`、事件产物等运行数据。只使用固定账号和时序数据可以启动一个新的业务环境。

完整反向代理与 CI 说明见 [自动化部署改造与验收说明](自动化部署改造与验收说明.md)。
