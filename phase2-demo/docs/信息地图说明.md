# 智能机舱：当前用户动线与信息产物

更新：2026-10-29。以当前船端路由、页面组件和 eventLifecycle 工作流为准。地图包含用户动线、信息总览、报警事件、预警事件、异动跟踪、状态与归属六个视图，以及可搜索的信息目录。默认打开用户动线。

入口：`docs/智能机舱-态势与事项信息地图.html`；发布副本为 `public/information-map.html`，工作区副本为 `../../doc/智能机舱-态势与事项信息地图.html`。三者由同一源生成，仓库内 docs 与 public 默认同步。本次只更新信息说明，不修改业务页面或历史测量。

## 当前用户动线

| 页面 | 入口与内容 | 下一步及关联产物 |
|---|---|---|
| 首页 | `/#/situation`；设备总览、近24小时工况态势与 AIS 回放、风险处置工作台 | 点设备进入健康与传感器；点事件进入阶段工作区；点报告独立查看全文 |
| 设备层 | 首页内部层级；健康概览、传感器数据两个页签 | 系统分区、六缸矩阵、运行参数、测点趋势；关联事件进入事件详情 |
| 事件中心 | `/#/issues`；设备、类型和状态筛选 | 查看全程、活动任务和已闭环记录；大管轮仅看本人参与事件 |
| 待办中心 | `/#/event` | 轮机长查看待我决策和执行中，大管轮查看当前执行任务；均进入同一事件工作区 |
| 事件详情 | `/#/situation/issue/:id` | 阶段条保存各轮记录；当前阶段按角色提供决策、执行或报告；右侧为 AI 检修助手 |
| 报告 | `/#/reports`、`/#/reports/:reportId` | 排查、维修、维保、闭环筛选，名称 / 编号搜索、全文与 Markdown 下载；当前不含工况报告 |
| 知识库 | `/#/knowledge` | 资料阅读与问答；引用供核查，不自动成为执行结果 |

首页轮机长工作台为“待决策 / 处置中 / 报告”，大管轮为“我的任务 / 报告”。待办不再仅指已派发任务，轮机长的待决策事项同样在其中；报告回交后重新进入轮机长待办。

事件初始阶段展示“风险提醒 / 数据观测 / 证据资料”。排查开始后以本轮步骤为主，原始资料从阶段条返回“已派发 · 风险提醒”回看。回交后展示处置决策或效果观察、阶段报告及本轮步骤。只有一项内容时不显示页签栏；没有独立“处置记录”页签。

## 初始事件列与后续生命周期

信息总览左侧“事件初始信息与首次分流”只展示三类 AI 事件、事件信息与排查建议、首次决策、初始待派草稿和首次确认派发。原“排查后再次决策”已合并到右侧“派发 / 回交 / 补充 / 闭环通知”；继续排查、派发维修、后续草稿与确认派发均在该生命周期步骤内接续。状态视图的全生命周期状态也放在右侧，后续操作不回连初始列。

## 决策、任务和报告的回路

1. 风险提醒 → 轮机长核对依据，查看待派排查草稿。
2. 负责人、未来完成时限、范围与草稿就绪后确认派发 → 创建独立任务并通知大管轮。
3. 大管轮逐项填实际结果；步骤与整表共用草稿，汇总结论必填，备注选填 → 提交一次形成报告。
4. 排查报告回交 → 轮机长再次决策。没有匹配异常结果时继续排查；有异常结果时派发维修。每次派发都创建新任务，旧轮报告保留。
5. 维修报告写入实际措施、复测结果和剩余事项 → 进入结果处置并开始该轮效果观察。没有独立验收表。
6. 轮机长可闭环、派发复查或同步岸基。复查无异常回结果处置；复查发现异常回处置决策。
7. 人工确认闭环生成闭环报告；事件中心、全部报告及阶段条保留回查入口。初始确认误报也会归档，但不生成虚构的执行记录。

当前 `lifecycleDecisions.js` 对三类事件共用上述菜单，**没有开放“关联维保单”动作**。维保数据结构、历史任务及报告展示仍兼容；维保不是第四类事件。旧演示脚本中的关联维保路线不能当作当前可点击操作。

## 中间产物与归属

| 产物 | 产生时机 / 内容 | 去向与边界 |
|---|---|---|
| 事件信息与排查建议 | 事件来源、数据含义、初判、未知项、建议排查范围 | 首次决策；不能仅凭指标确认根因 |
| 待派任务草稿 | 范围、依据、步骤、来源报告、版本、生成状态 | 轮机长审阅后确认派发；草稿不是任务 |
| 本轮任务 | 独立任务 ID、类型 / 用途、轮次、负责人、时限、批准范围、来源报告 | 大管轮执行；报告提交后不自动转为维修任务 |
| 步骤反馈 | 每项结果、备注、汇总结论、附件索引 | 汇总为人工提交的排查/复查反馈或维修反馈 |
| 排查/复查反馈 | 人工提交检查结果、原因判断、待核实项 | 作为处置报告输入，不自动启动维修 |
| 维修反馈 | 人工提交实际措施、复测结果、完成情况与剩余事项 | 作为处置报告与效果观察依据 |
| 处置报告 | AI 整理人工反馈、证据与范围、原因解释、未核实项和建议处置；补充修订并入同一报告 | 回交轮机长复核，保留原始反馈、旧版本和补充原文 |
| 效果观察 | 结合维修反馈与传感器信息：标准化测点、时间、单位、工况、窗口汇总和缺测状态 | 结果处置；后续派发或闭环后留存本轮观察 |
| 派发 / 回交 / 补充 / 闭环通知 | 流程步骤：派发进入执行，回交进入再次决策，补充进入复核，闭环进入归档 | 衔接事件生命周期阶段与接续角色；报告补充保留当前阶段与任务关系 |
| 闭环报告 | 人工依据、确认人、时间、历轮材料 | 归档与回查；事件闭环不能解释为设备长期完全恢复 |
| 岸基同步快照 | 同步原因、当时事件 / 任务 / 报告 / 决定的快照 | 当前状态为“待岸基接收”，不证明实际送达岸端 |

任务草稿在当前阶段和报告基础上生成，生成失败保留错误或原可用版本。普通 AI 问答失败可回退已有规则建议；报告修订失败不覆盖原报告。报告补充只允许事件未闭环时由大管轮对本人报告确认写入，并检查基准版本与重复应用。

## 节点属性与状态

- “角色与权限”说明轮机长与大管轮的可见范围和操作职责。
- 报警事件、预警事件、异动跟踪和处置报告均标记为 AI 产物；排查/复查反馈、维修反馈属于人工提交。
- 派发 / 回交 / 补充 / 闭环通知归流程步骤，说明生命周期阶段衔接。效果观察同时连接原始传感器来源、标准化结果和质量 / 工况核验。
- 补充修订并入处置报告；不再单列报告补充修订稿、角色会话与 AI 依据节点；用户动线不展示日志中心。

## 状态与实际实现边界

- 事件状态包括待决策、排查中、待处置决策、维修中、复查中、待结果处置、已闭环；维保执行中用于兼容已有任务。事件中心筛选暂未单列“复查中”，卡片仍可显示该状态。
- 任务状态为已派发 `assigned` / 已提交 `submitted`；待派草稿另外保存。复查在内部是 `investigation` 类型、`purpose: recheck`，与排查共用该类型的轮次计数。
- 当前效果观察由 `eventLifecycleStore` 以 `demo:true` 获取演示采样，不能作为实船修后验证。当前闭环操作要求轮机长在结果处置阶段填写依据，代码没有把完整观察窗口达标设为硬性门槛。
- 任务、报告、通知保存在同源浏览器，页签各自保留角色。此角色切换不是生产账号权限系统。
- 岸基同步是本地待接收记录。地图只描述这一边界，不扩展成已经完成的船岸联动。

```powershell
node scripts/build-information-map.mjs --sync-workspace-doc
node scripts/build-information-map.mjs --check --sync-workspace-doc

```

地图可离线打开，不加载外部脚本、样式或数据库。文件方式打开的船端入口指向本地 5173；HTTP(S) 发布保留同站相对路径。源码路径只作溯源说明，不是外部下载链接。
