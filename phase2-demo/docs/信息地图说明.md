# 智能机舱三类事件与真实资料案例

更新：2026-10-22。HTML 与船端共用 `src/mock/realCases.json` 的历史证据。产品仅保留 **报警事件、预警事件、异动跟踪** 三类事件；原维保条目作为父异动跟踪中的建议和执行子任务保留，历史原文与原始测量不重写。

## 查看入口

- 信息地图：[独立页面](../public/information-map.html)，开发及发布站点路径为 `information-map.html`。进入报警事件、预警事件或异动跟踪，切换 **真实案例**。异动跟踪中包括临修后健康跟踪、维保建议、人员确认、评估执行和结果回写，不再提供独立维保事件导航。
- 船端：打开站点的 `/#/situation`（本地开发为 <http://127.0.0.1:5173/#/situation>）查看船舶与设备态势；事件统一进入 `/#/issues`，可按设备筛选。当前包括 0430 报警、0523 预警、0816 异动跟踪与 0523 临修后健康跟踪，共四条事件、三类事件；0523 的两条事件共享同一来源问题。
- 全部事件使用 `/#/issues`；确认派发后创建的任务在 `/#/event` 待办任务中推进。事件目录与待办任务按不同对象组织，派发表单未确认或已取消时不会创建任务。
- 0523 后续维保：进入父跟踪 `real-health-0523` 的 **事件概览** 页签，查看阶段性维保建议并确认评估安排。实际评估／执行子任务仍使用 `real-maintenance-0523`，可沿现有派发与待办流程推进，结果关联回父跟踪。
- 历史证据与当前产品操作分别保留。新增观测值默认待人工判读；填写一个数值或一天记录，不会自动证明效果稳定、完整覆盖观察窗口或允许闭环。

## 三类事件、维保子流程与结果边界

| 类型 | 真实来源 | 产品中的最终节点 | 不能据此声称 |
|---|---|---|---|
| 报警事件 | 0430 二缸 ICU 伺服油液压活塞卡阻 | 已有更换和测试正常的船端报告；持续效果与正式关闭签认待补 | 采样窗口内已完成维修、已正式关闭 |
| 预警事件 | 0523 控制空气双测点低压及减压阀故障 | 临时恢复已有资料；操作时间与修后可比采样待对齐，永久措施待证据 | 临时修复就是永久修复；报警后回升就是已验证的修后效果 |
| 异动跟踪 | 0816 负转燃烧与倒车操纵核实 | 后续轮机长反馈支持正常操纵，原样本按无需处置关闭；演示本轮核实结束 | 单凭负 RPM 确认 TDC/启动系统故障；已取得长期健康恶化数据 |
| 异动跟踪中的维保子流程 | 同一 0523 来源事件的临修后健康跟踪 | 人员确认后演示必要性与条件评估，结果回写父跟踪；保留 HRD-FA 永久措施、备件和验证需求 | 已观察到新的连续劣化趋势、已有正式维保工单或永久更换已完成 |

这是 **3 起来源事件、3 类产品事件**。0523 预警与后续临修健康跟踪共享来源，不能重复计为两起真实故障；维保建议不是第四类事件。已有档案、交互回放和执行子任务也不是新增的真实故障。平台派发、提交、阶段切换和父跟踪回写是可操作的产品改编，逐步标识；真实操作及检查结论仅按来源记录。

维保建议只能从异动跟踪的事件概览中进入：观测发展及现场依据支持建议 → 人员确认 → 必要性和条件评估 → 按实际发现执行及验收 → 观察效果并回写父跟踪。资料不足、暂不采纳或本轮不提前处理均保留父跟踪与原计划，不自动证明设备恢复。

| 原建议／执行项 ID | 父异动跟踪 ID | 保留的关系 |
|---|---|---|
| `maintenance` | `bearing-health` | 连杆轴承健康趋势与提前评估 |
| `aux-maintenance` | `aux-health` | 辅机健康跟踪；健康来源链仍为 `aux2-health` |
| `real-maintenance-0523` | `real-health-0523` | 0523 临修后健康跟踪；关联原预警 `real-warning-0523` |

旧执行项 ID 用于继续原评估／执行流程，通过 `parentIssueId` 关联父跟踪，并以 `workflowKind: maintenance` 标识工作类型。它不再出现在独立事件类型筛选或首页事件计数中。地图的0523走读入口为父跟踪，原历史案例身份保留在 `sourceCaseId`。

## 页面组织

- 态势首页保留船舶图、原 AI 总结分析与事件处置。
- 设备页仅保留 **健康概览／传感器数据** 两个页签。健康概览依次展示健康研判、默认折叠的详细研判、重点系统测点；不再保留独立健康监控模块、动态记录或相关事件页签。
- 健康概览的重点测点与 **传感器数据** 复用系统分区、完整 1—6 缸矩阵和运行参数组件，点击读数查看趋势。历史月统计和跨月比较保留为数据口径，不表示当前页面存在独立入口，也不与当前读数混用。
- 关联事件统一使用 `/#/issues?device=...&type=...&state=...`；事件仅使用 **待决策／处置中／已闭环** 三种状态。待办 `/#/event` 只显示 **处置中** 任务；闭环后仅从事件中心 `/#/issues` 回查完整记录。

| 任务结果与闭环建议 | 分别保留报警、预警、异动核实、维保任务的完成结果、资料限制、闭环建议和人工确认 | 本轮完成、设备恢复、来源事件闭环分别按证据判断；维保结果回写父跟踪 |

重复信息已合并：测点映射与标准化合为一张卡片；质量与运行工况合为一张卡片，周期统计另列；OEM 报警关联不再独立显示。误报／忽略的人工反馈归入分流决定；派发记录与待办概览归入任务推进。确认派发仍是独立门槛，直接连接三类事件对应的任务。

原末列的态势页、待办中心、知识库等页面容器已移出主信息链。页面入口和来源仍可在节点详情中回查。三类事件的流程图把派发后的调整、排查、评估和执行放在任务列，把完成确认及结果回写放在结果列；不把这些推进动作混在事件的决策分流中。

这里描述当前原型的信息组织和流转约束，不声称新增映射、持续检测或诊断算法已经部署。原型中的案例和演示资料仍按各自证据边界展示。

## 来源与复跑

以下路径均相对于 `phase2-demo`。地图可作为独立页面打开，样式、脚本、图谱数据均内嵌；不加载外部字体、脚本、图片或数据库。真实案例链接在 HTTP(S) 站点中使用同站相对路径，保留发布子路径。仅从本地 `file://` 打开 HTML 时，链接转向已有本地应用 `http://127.0.0.1:5173/`；发布站点不跳回 localhost。

| 文件 | 作用 |
|---|---|
| `public/information-map.html` | 可独立打开的发布产物，Vite 构建会复制到 `dist/information-map.html` |
| `docs/information-map/model.json` | 当前信息图谱、三类事件流程和案例展示覆盖，不复制历史采样序列 |
| `docs/information-map/template.html` | 信息地图的 HTML、样式及交互渲染模板 |
| `src/mock/realCases.json` | 与船端共用的真实案例、采样及来源证据 |
| `scripts/build-information-map.mjs` | 读取上述源文件、校验引用与证据边界并生成单文件页面 |

在 `phase2-demo` 目录运行（仅使用 Node.js 内置模块）：

```powershell
node scripts/build-information-map.mjs
node scripts/build-information-map.mjs --check
npm run build
```

`--check` 验证发布文件与当前生成源一致。生成时还检查五个视图的固定名单、节点引用和合并别名、六层顺序及节点归属、原始输入到加工、事件到确认派发、任务到推进和结果的可见连通性、场景不绕过映射结果、任务必须来自确认派发、末列不含旧页面容器、三类事件导航、维保子流程可达性、案例阶段，以及历史采样、时间线、来源和限制没有被展示层覆盖。不需要本地原始数据库或 `.runtime` 目录，也不会重新运行检测／诊断模型。

在完整工作区中，如需同步外层 `doc/智能机舱-态势与事项信息地图.html`，显式使用以下选项；独立发布项目无需此外层目录：

```powershell
node scripts/build-information-map.mjs --sync-workspace-doc
node scripts/build-information-map.mjs --check --sync-workspace-doc
```

本地图的源结构由本地已审阅的信息地图整理而来；外层 `doc/智能机舱-态势与事项信息地图.html` 与发布产物同步为同一份内容。历史资料中的本地文件路径用于说明来源，不是在线下载链接。数据库、原始附件、临时截图、运行日志与凭证不包含在发布包中。
