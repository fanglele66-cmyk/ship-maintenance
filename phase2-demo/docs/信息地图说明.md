# 智能机舱信息地图说明

更新日期：2026-10-30。此地图依据当前页面、业务状态和路由更新；文档要求与尚未实现的能力分开说明。

## 事件、任务、待办

事件是持续的问题档案，关联原始提醒、各轮任务、现场反馈、报告、决定和观察。任务是人员确认派发的一次独立工作。待办连接某个人与当前需要处理的工作，不复制事件或任务记录。

| 入口 | 进入哪里 | 当前内容与权限 |
|---|---|---|
| 首页“值得关注” | 事件、本人任务或报告 | “查看全部待办”进入待办中心；工况态势按从左到右的时间序列呈现 |
| 事件中心 | 原事件当前阶段工作区 | 风险提醒与阶段条保留，历轮任务、报告和观察可回查 |
| 决策／确认待办 | 原事件本轮工作区 | 轮机长在同一处审阅结果并决定下一步，不另开重复审阅待办 |
| 执行待办 | 独立任务详情 `/#/tasks/:taskId` | 执行人处理本人任务，轮机长查看已派发任务进度 |
| 我派发的 | 同一任务详情 | 仅轮机长可见；派发后该执行任务不再占用轮机长待我处理 |
| 已完成／全部记录 | 历史任务或决定 | 按角色和实际状态展示；当前任务完成判定的差异见下文 |

任务详情只保留本轮任务名称、编号、派发人、执行人、时限、关联事件、批准范围、执行记录和报告。左侧步骤与右侧表单共享草稿，不再设置任务证据资料页签。提交后，查看报告与通过对话补充报告并排放在左侧；补充仅限执行人本人报告，闭环后不可补充。

## 建议与派发

初始风险提醒下提供“AI排查建议”。轮机长可以通过对话修改草稿，再通过“去派工”填写负责人和完成时间，确认后才创建执行任务。

排查回交或进入观察后，未选择派发动作时不展示下一轮任务建议。选择继续排查、派发维修、提前维保或派发复查后，才显示相应的“AI排查建议／AI维修建议／AI维保建议／AI复查建议”。改选观察、闭环或岸基同步时，收起建议页签及对话修改入口。建议草稿不是已派任务。

首轮建议、后续建议、确认派工和已派任务的范围分别保留；新一轮任务不覆盖旧任务及报告。排查、复查反馈步骤为1—4项，维修明细合并为最多4个反馈步骤。

## 反馈、报告与后续决定

1. 执行人提交逐项实际结果和汇总结论，原始记录先保存。
2. 大模型根据本轮事实流式整理报告。完整结构校验通过后才写入报告并交轮机长；失败保留原记录并支持重试。
3. 轮机长根据实际业务问题决定下一步：具体异常有处理依据时维修；异动核实后可选择维保计划和靠港窗口提前维保；仍有疑点可继续排查，也可继续观察或说明依据后闭环。
4. 执行人通过对话补充报告时，核对修订稿后写入同一报告，保留原始反馈、旧版本和补充内容，再提醒轮机长复核。
5. 闭环报告串联事件基础信息、原异常、历轮检查、原因判断、实际措施、观察反馈和人工关闭依据；未实施的工作不写成已完成。

异动跟踪先判断相对排温变化是否成立。“不支持四缸基线下移”“尚缺可比资料”和“未发现某部件缺陷”是不同结论，不能互相替代。原统计变化及来源保留，现场核实结论与解释单独呈现。

## 观察与提醒

- 核实后继续观察：轮机长决定暂不处置，包括异常自行回落后的跟踪。事件内观察变化是否持续、扩大、恢复或复发，不新建人员执行任务。
- 处理后效果观察：关联实际维修／维保反馈与复测；当前实现回交即采样，正式观察确认门槛仍需补齐。
- AI观察建议仅轮机长可见，可关闭建议栏；最终闭环、复查、继续观察由轮机长决定。核实后观察也可选择维修。
- 明确继续观察后，等待期间不产生人员待办；窗口结束形成审阅观察结果的决策待办。普通采样更新不复制待办。
- 事件未决策时铃铛提醒持续保留，弹窗只显示最新一条。阅读或关闭弹窗不等于完成决定。

## 与二缸报警业务流转文档的核对

已具备：事件持续归档；每轮独立任务；按角色分开的执行与决策入口；报告保留原因未明和未完成项；模型流式报告及补充修订；人员派发维修；核实后观察、复查和人工闭环；任务／事件／报告的双向回查。

仍不完全一致的部分：

| 文档要求 | 当前实现 | 差异 |
|---|---|---|
| 按要求完成检查并交付结果，排查任务即可完成，不必等下一步决定 | 提交后 `goalStatus=awaiting-review`，轮机长下一步决定才更新为完成或未完成 | 已完成检查的核实任务仍可能停留反馈待审阅 |
| 轮机长确认本轮处置目标和正式观察安排后开始观察 | 维修／维保回交后即进入结果处置并开始采样，另可选择继续观察 | 正式观察开始早于确认 |
| 等待适用工况时明确证据不足，不能单凭时间判定验证通过 | 已有窗口质量与两小时建议规则，仍使用内置采样 | 尚缺完整的设备运行、负荷可比性与条件恢复机制；原两小时闭环建议需与文档口径进一步统一 |
| 未做完检查可提交阶段报告，选择等待后沿用原任务继续 | 可提交受限记录和报告，但尚无等待条件、恢复原任务、调整执行人或明确终止的完整操作 | 此分支不能完整走通；AI观察不能替代人员任务等待 |
| 事件档案固定包含当前情况、当前安排、完整过程 | 已有阶段条和历史回查，内容仍随当前阶段切换 | 稳定的事件总览结构尚未统一 |
| 新证据要求改范围时交轮机长决定 | 已派任务不允许AI直接修改，但缺少主动申请调整的完整入口 | 新证据到范围调整尚非完整回路 |

文档本身尚待确定的接口与规则不视为已完成：真实报警采集／事件合并、闭环后再次异常的关联判断、转派授权、等待条件确认、正式船管工单联动、岸基接收回执。

## 数据与实现边界

历史测量、来源、统计、冲突和限制继续从 `src/mock/realCases.json` 只读引用，地图不改写原始证据。页面的流程记录与历史资料分别保存；当前自动采样使用内置数据源，不代表已接入船端实时采集。模型问答、报告生成与建议调用本机后台配置的模型；后台密钥不进入前端或地图。

任务、报告、决定与提醒目前保存在同源浏览器；角色切换不是正式账号权限系统。岸基同步保存待接收快照，未接入岸基接收服务。提前维保任务保存计划与靠港窗口快照，未读写正式船管工单。
