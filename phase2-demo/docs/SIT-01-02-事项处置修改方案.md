# SIT-01 / SIT-02：事项处置修改方案

## 1. 范围与授权

2026-10-13 基于公网 V18 已确认方案执行。只调整船舶态势工作台事项模块、独立事项总览以及共用事项行与信号灯规则。设备页签、详情内容、模拟故事、任务阶段及人员指派流程不重新设计。共用事项行的颜色与动作措辞会同步到复用它的设备相关事项列表。

## 2. SIT-01：工作台事项处置

- 模块标题与 AI船舶态势分析继续共用 ModuleHeader。
- 删除标题右侧查看全部入口，恢复设备选择器（默认全部设备）。设备选项主机、舵机、空压机、锅炉，不由当前有无事项决定是否出现。
- 保留待决策/已派发页签，设备筛选对两类都生效。去除页签及底部数量，不增加未经定义的计数。
- 底部唯一入口为“查看全部事项”，无计数；无论本类是否超过4条，入口保持可见。进入大全时清除外层筛选，不继承设备和派发状态。
- 保留当前最多4条摘要及空态引导，不增加新的详情内容。
- 优先按类型排序：报警事件 > 预警事件 > 异动跟踪 > 维保建议；同类型按设备影响力：主机 > 舵机 > 空压机 > 锅炉；再按真实更新时间倒序，无时间数据保持稳定顺序，不编造时间。
- 类型标签两档：报警/预警红色，异动/维保橙色。同档同色，名称区分类型。
- 信号灯：存在未闭环报警/预警红色；仅异动/维保橙色；没有活动事项绿色。派发本身不提升信号灯等级。已记录忽略决定不视为活动事项。
- 右上角统一：待决策“查看分析”；已派发“查看进展”。整行点击和键盘可达保持一致；状态页签内不重复状态标签。

## 3. SIT-02：事项总览

结构：返回及标题 → 三个筛选器 → 独立滚动列表 → 加载更多/结束提示。

- 进入默认完整未闭环清单。设备=全部设备，事项类型=全部类型，派发状态=全部状态。
- 状态筛选仅全部状态/待决策/已派发，无状态页签。设备筛选使用同一设备字典；类型使用同一四类字典。三个条件取交集。
- 排序：待决策在前、已派发在后；每组按类型优先、设备影响力其次、更新时间再次排序。
- 首批10条，点击加载更多再增10条。不并列增加分页器或自动无限滚动。条件变更回首批并滚至顶部。
- 底部不显示数量。结束时“已显示全部符合条件的事项”。无符合项提供清除筛选；全部未闭环事项为空时说明当前情况并可返回态势。
- 每行共用 CaptainIssueRow。混合状态清单显示状态标识，右上角查看分析/查看进展；摘要、负责人/阶段沿用已有内容。外层页签列表省略状态标识。
- 进入详情再返回，保留筛选、加载批数、滚动位置；工作台新进入大全则恢复默认全部。已派发记录仍进入原待办，不复制事件。

## 4. 视觉与组件规范

复用 ModuleHeader、FormSelect、BackButton、CaptainIssueRow。总览根容器填满 app-content 剩余宽高，明确 flex伸展、width:100%、min-width:0、box-sizing。三个带标签选择器常规桌面同排左对齐，窄窗口自然换行。标题、筛选固定，仅列表滚动。长摘要正常换行，右侧动作不被挤出，不强制拉长内容文字行。

验收尺寸：1920×1080、1536×864、实际浏览器窗口；无横向溢出，页宽填满，筛选器无截断，底部入口可见。

## 5. 验收清单

- 入口仅一处、无计数，工作台设备筛选生效。
- 报警和预警同红；异动和维保同橙；派发低级事项不使灯变红。
- 混合设备排序严格类型优先；总览严格待决策优先。
- 总览首次进入全部；三条件交集；无结果可清除；结束提示无计数。
- 10/20条边界与加载更多；筛选重置批数、滚动位置。
- 详情往返保持条件/批数/位置；再次从工作台进入恢复全部。
- 原设备详情、维保计划、待办流转保持可访问；观察归档不等于事件闭环。
