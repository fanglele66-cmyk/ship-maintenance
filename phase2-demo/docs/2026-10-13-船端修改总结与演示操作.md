# 2026-10-13 船端修改总结与演示操作

范围：船端。源码分支phase2-demo-20261009，本日迭代为本地开发与Sites公网更新；本次GitHub交付范围包含下述功能和材料，版本以本文件所在提交为准。本文件对应今天已确认的修改，不把规划内容当作已开发能力。

## 今天的修改方向与方案

| 方向 | 处理方式 | 对使用者的作用 |
|---|---|---|
| 轮机长工作台与事项总览 | 事项类型优先级、设备筛选、待决策/已派发区分；首页最多5条、底部查看全部；总览三筛选及分批加载；派发回发起清单 | 先判断要看什么，再逐个安排，不自动跳入执行人的待办 |
| 事项详情结构 | 事项概览/研判分析/证据资料三签；结论建议在前，可展开推理，证据备查，决策表单在概览底部 | 快速判断与完整备查兼顾，不将未确认原因当作故障结论 |
| 设备态势规范 | 设备名与返回统一；健康概览适配；相关事项改为事项类型+事项状态并排筛选，默认全部类型+待决策；状态为待决策/已派发/已结束 | 少一层页签，设备范围明确，可查历史决定和闭环材料 |
| 动态与周期计划 | 撤销额外加入的独立系统跟踪板块，恢复动态记录；保留常规维保计划独立入口 | 动态列表保持原框架，提前建议不替代原周期计划 |
| 全局通知故事 | 右上铃铛，18秒后只弹一次空压机异动跟踪通知，复用现有事项材料 | 演示收到变化提醒→了解依据→轮机长决策的自然过程 |
| 详情适配与AI事项助手 | 去掉事项正文独立1100px限制，复用左右分栏；消息/输入/历史组件共用，事项会话独立 | 标题正文同栏，证据随可用宽度排布；助手围绕当前事项一问一答 |

助手名称按实际层级区分：设备页AI设备态势助手；事项详情AI事项助手；待办具体执行检修助手。全船工作台保留左侧AI船舶态势分析。

## 推荐演示顺序

### 故事一：轮机长先看全船，再决定一个主机事项

1. 刷新进入态势中心，先读AI船舶态势分析，再查看事项处置。主机风险优先，报警/预警用红色，异动/维保用橙色。
2. 点击孪生图主机，进入健康概览，了解综合判断、依据和安排建议。
3. 进入相关事项，默认全部类型+待决策。可筛选预警事件，打开润滑供油异常预警。
4. 左侧先看初判结论与建议、关键依据；右侧AI事项助手自动显示用户问句“查看主机……的判断依据和处理建议”，随后给出对应答复。
5. 点击右侧“还需核实哪些信息？”，得到当前材料的证据与缺项；点击回复中的“查看证据资料”，左侧切到证据签，不产生新的事件或待办。
6. 问“下一步如何安排？”，助手引导到左侧决策区。点击采纳建议并指派，用原标准表单选择负责人、任务类型与安排，确认后回到原发起位置继续决策。
7. 查看已派发事项，再进入原待办了解进展。待办内沿原一期概览→排查→维修等流程处理，助手为检修助手；新建检查类事项先核实真实性，不直接跳维修。

### 故事二：收到空压机异动通知

1. 刷新页面，停留态势中心约18秒。收到空压机加载时间持续延长的简短提醒，右上铃铛出现红点。
2. 点击“查看并处理”，进入原空压机事项详情，右侧打开AI事项助手；此动作只打开材料，不自动建待办。
3. 看95→112→128秒加载记录、压力仍可达0.82MPa等证据，了解为什么需要核实而不能直接判机体磨损。
4. 可以采纳并指定负责人，或忽略本次建议并记录依据。忽略不代表设备正常；派发不等于闭环。
5. 关闭浮动提醒不等于已读或已处理；从铃铛可以再查看。已派发后通知入口改为查看进展，沿同一待办继续。若18秒前已作决定，不再弹陈旧的待决策提示。

### 故事三：提前维保与常规计划分别查看

1. 主机→相关事项→维保建议，查看连杆轴承提前检查建议。
2. 比较振动变化、累计运行小时、周期节点和靠港窗口，先评估是否需要提前检查，不能直接决定换件。
3. 查看常规维保计划，原2000h周期与140h差值保留。拒绝提前建议，不改变原周期计划。
4. 通过已结束筛选回查不采纳依据；实际执行记录和动态由原关联任务接续。

## 对话与操作边界

- 一问一答；切换左侧页签不会重新发送首问；返回同一事项保留会话和草稿。
- 每条事项独立上下文，不借用其他设备的旧对话；初始至多两个了解型追问。
- 助手只解释当前材料、链接证据和决策区，不在右侧复制一份指派表单。
- 报警、预警、异动、提前维保的下一步不同；未核实前不直接确认故障或安排换件。
- 已处理作业、观察结束、原事件闭环是不同概念；已派发后继续原任务，不重复创建。
