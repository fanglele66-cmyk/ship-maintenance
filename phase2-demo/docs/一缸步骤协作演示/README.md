# 一缸排温长期基线抬升跟踪 · 步骤协作

事件：CBY-EVT-20260812-001（`real-tracking-exhaust-baseline`）。本目录参照二缸目录，提供从任务开场到提交报告的完整操作路径和可直接发送的原话。

## 入口与流转

1. 轮机长打开一缸事件初始信息，选择“派发排查”，执行人为李建国（大管轮），要求完成时间选择当前时间之后。切换为大管轮，从任务页进入两步排查。
2. 按[排查脚本](排查演示脚本.md)填写、核对并提交。
3. 轮机长审阅排查报告，确认“异动成立、部件原因未定”，选择“提前维保”。在维保计划中选择 CBY-MP-BALANCE-01“一缸测温与燃烧平衡专项维保”（4 步），不要选择默认的 3 步测温保养计划。选择仍有效的靠港停机窗口，要求完成时间必须在该窗口内；当前预置上海 2027-01-31 09:00—16:00、宁波 2027-02-02 08:00—15:00。确认计划、负责人和窗口后派发，再以大管轮进入维保任务。以下作业描述对应所选窗口内的执行路径，不表示在窗口之前已经作业。
4. 按[维保脚本](维保演示脚本.md)逐步记录。本路径包含未完成验证，提交后保留剩余事项，由轮机长安排等待条件或剩余任务，不直接宣布闭环。

## 操作约定

每个任务只有一个助手。开场只出现一次，切换左侧步骤继续使用本任务对话，不重复开场。左侧不需要 AI 协助按钮；直接在右侧发送即可。附件、图片和语音入口在输入框底部，发送前核对内容。

原话完全匹配时使用固定回复，先展示分段处理进度，再给一句追问或备注草稿。追问等待合计约 1.6 秒，草稿约 1.8 秒；这是处理状态，不是外部模型的推理。脚本外新事实或改写仍调用当前配置的真实模型，并携带本任务上下文；不要把其他步骤内容当成本步已执行证据。

信息不足先追问，不会每次都给草稿。草稿出现后，输入框上方选择“采用到本步骤”，再点“确认”；只写本步备注，不自动选择结果、换步或提交。选择“继续修改”后点“确认”会点亮输入框，再发送补充；在有可选修订的步骤，可使用下文给出的修订原话。

每个主步骤可独立开始，不必完成上一主步骤的可选修订；补充回答仍需本步前文。先选结果再采用、先采用再选结果都可；若结果与描述冲突，助手先简短核对。采用后按橙黄色“下一步”提示手动切换左侧步骤。必填结果齐全时导航变绿，只代表填写齐全。

提交后任务助手最前的两句自我介绍保持不变，报告进度与提交回执在后续消息显示，不向引导语追加状态。报告页仍按现有生成流程工作，固定对话不包含最终报告生成；生成失败时保留已提交事实记录，可重试。

已有派发任务是快照；进入前核对本目录列出的步骤标题与数量。旧任务或人工改过的方案若不一致，按其实际范围执行，不覆盖已有记录。轮机员提交前到任务页查看和填报，提交后事件页显示本轮只读记录。
