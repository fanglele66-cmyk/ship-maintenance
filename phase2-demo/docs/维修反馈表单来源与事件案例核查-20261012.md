## 2. 必须保留的流转差异

- 关注核实、异常确立、排查、维修、效果观察与事件结束并非每次必经的固定直线。
- 一期排查的正常结果转向其他待排查项；异常结果打开对应维修项，且保留本轮现场反馈。
- 一期维修验收未解决时继续其他排查；若没有剩余项则显示仍需人工处理，不应写成已解决。验收通过才走解决分支。
- 当前二期检查反馈允许实际结果保存；只有已支持的结果组合推进。其他有效结果保存而不推进，这不能宣称已经实现全部诊断分支。
- 当前执行记录的 completed/partial 表示执行是否完成；它不等于维修是否解决原异常。comparable 表示有无可比数据，也不等于验收通过。
- 当前二期修后效果还存在稳定、异常反复、数据不足三种结果，并有延长观察和回到原事项排查的接续。人工处理完成、效果观察结束、事件结束应分别理解。

## 3. 上轮新增结构的问题归属

AdditionalTodoDetail.vue、additionalTodos.json 与 supplemental 分流均为我本地上轮新增，并非组长版本。它们是独立只读材料，未接入原事件的检查反馈、执行草稿、右侧会话及效果接续。设备概览和当前待办的关联也不完整。不得把这些页面视为已完成的事件模拟。
