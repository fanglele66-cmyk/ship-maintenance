# 四事件交互演示脚本

更新：2026-11-03。按当前本地工作区核对，覆盖全部 11 种决策动作、各阶段菜单及非顺利路径。本文是原型操作脚本，案例反馈文字是演示输入，不代表新增实船检查事实。

本版变化：轮机长直接派发，轮机员执行；派发表单不再填写“安排范围与依据”；效果观察不再填写“决定依据与后续安排”；决策不经 AI 整理预填；人工报告先回交、AI 分析随后补充。轮机长的填写进度、已提交逐项结果和报告快捷入口保留。

**本轮新增已实施**：新独立存储会话固定时间 T，报警 T−1 小时、预警 T−3 小时；同源刷新/切角色/新页签保持不变，既有人工记录不重置。一缸/四缸月度案例仍保留历史时间。工况态势按角色展示：轮机长只看设备、类型数量和处置概况，具体事件入口在“值得关注”；轮机员只看通用工况。全站内置设备内容统一为单台辅机。

### 最新追加：报告编辑及决策入口

1. 事件内仅顶部保留“填写决策”。初始信息底部、AI 分析及效果观察正文、事件助手内的重复按钮已移除；建议页没有“去派工”，核对建议后使用顶部填写决策。查看历史阶段时，顶部仍按当前状态打开决策菜单。
2. 点“上报岸基”，可直接修改完整正文，也可切换“预览报告”，确认后上报；正文不能全部留空。关闭未提交的同一稿件后再次打开，人工修改保留。
3. 在事件内“上报岸基报告”页签，或侧栏报告中心的该报告详情，点“修改报告”修改正文，再点“保存并重新上报”。生成新的上报版本并保留原版，刷新后仍可回看；船上事件状态及原排查/维修报告不受影响。

### 本次追加：工况、关注进展与事件内岸基报告

1. 工况区显示航行变化、负荷变化，移除供电方式和暂停按钮，默认播放；负荷趋势是阶段特征，不重复瞬时负荷值。
2. 待决策显示具体阶段；处置中显示执行人、填写数量、完成期限和更新时间。草稿数量不等于已完成，未提交正文仍仅执行人可见。观察进行中显示系统观测和计划汇报时间，回交后转观察后决策。
3. 独立报告卡片和详情都有所属事件链接。报告入口移至左侧任务下方；首页轮机长仅待决策／处置中，轮机员仅我的任务。态势及其他导航图标在选中／未选中状态均应可见。
4. 打开四缸事件，上报岸基 → 编辑或预览本次上报内容 → 确认上报岸基。自动进入事件内部“上报岸基报告”页签，状态为“已上报岸基”；正文按当前情况、事件发现、排查与处置经过、当前判断与待解决事项、后续安排整合为一份报告，原报告在折叠索引中。事件仍待决策。
5. 再次上报后切换第 1／2 次记录；刷新后记录保留。后续新增报告或 AI 更新不改变旧快照；下一次上报包含最新正式报告。上报页签的原报告索引可打开报告，再返回对应事件。
6. 在关联效果观察中上报，基础报告同时包含源事件及观察事件已有资料；不包含其他独立案例，也不包含未提交草稿。按用户确认采用原型上报流程，显示“已上报岸基”，暂不接真实接口，不伪造岸基回执；上报不代表事件闭环。

2. 右上角角色：陈志远（轮机长）、李建国（大管轮）、王海（二管轮）。后两者均为执行人员，只能执行自己的任务；没有大管轮授权派工这一步。相同浏览器源内共享流程数据，每个页签可保留不同角色；不同端口不共享。

## 2. 全部阶段与决策菜单

先判断是否已闭环/已转观察，再看当前任务是否等待、执行中或有未完成事项，最后判断报告后的决策阶段。“上报岸基”始终通过页面独立入口可用，按原型流程显示已上报岸基并保存完整快照，不改变船上阶段，暂不接真实接口。表内不重复列它。

| 编号 | 当前条件 | 可选决策 | 结果与边界 |
|---|---|---|---|
| D01 | 初始信息，尚未派发 | 派发排查、确认误报 | 不能直接维修、观察或普通闭环；确认误报必须写依据 |
| D02 | 当前任务待执行 | 无其他处置决策 | 等待执行人提交；可查进度和已提交历史记录 |
| D03 | 人工报告已回交，AI 生成中或失败 | 按正式反馈进入下列分支 | AI 状态不阻塞轮机长决策；重新派工或闭环后旧 AI 结果不能覆盖新状态 |
| D04 | 排查存在明确未完成/受限，且无匹配异常 | 继续排查、等待条件，保留原任务、终止未执行部分、说明剩余事项并闭环 | 继续排查建新任务；等待保留旧任务；闭环必须明确剩余事项处置与承担人 |
| D05 | 排查受阻且有匹配异常，或维修/维保有未完成事项 | 派发剩余维修、等待条件，保留原任务、终止未执行部分、说明剩余事项并闭环 | 不能把未完成工作转成效果验证通过；剩余维修派新轮次 |
| D06 | 原任务在等待条件 | 条件具备，恢复原任务、终止未执行部分 | 恢复沿用任务 ID、执行人和已完成记录；可更新完成时间 |
| D07 | 未执行部分已终止 | 闭环、派发复查 | 终止任务不等于事件闭环；仍需后续决定 |
| D08 | 排查已回交，异动核实成立且无明确部件异常 | 提前维保、效果观察、闭环 | 仅一缸/四缸异动满足判断时出现提前维保；需选择计划及有效靠港窗口 |
| D09 | 排查已回交，有匹配异常结果 | 派发维修、效果观察、闭环 | 异常结果包括“发现异常 / 读数不一致 / 偏离仍存在”；有菜单不等于确诊部件损坏，需审阅方案 |
| D10 | 排查已回交，未匹配异常也未确认异动 | 继续排查、效果观察、闭环 | 原因未知不自动等于作业未完成；观察仍受未完成事项校验约束 |
| D11 | 维修/维保完成后的结果处置，或无异常复查后 | 闭环、派发复查、效果观察 | 原事件选择观察后新建独立效果观察事件 |
| D12 | 排查后建立的“核实观察”，已到期待审阅 | 闭环、派发复查、派发维修、效果观察 | 可继续观察；派发维修仍先审阅待派方案 |
| D13 | 维修/维保后的效果观察，已到期待审阅 | 闭环、派发复查、效果观察 | 需新增维修时先复查；复查发现异常后按 D09 派发维修 |
| D14 | 效果观察正在等待计划时间 | 闭环、派发复查；核实观察另有派发维修 | 不显示重复“效果观察”；通常等到期报告，需要提前处理时由轮机长明确决策 |
| D15 | 原事件已转效果观察 | 无原事件新派工 | 从关联观察事件继续，原报告和任务可回看 |
| D16 | 事件已闭环 | 无新处置决策 | 回看/下载报告；仍可保存岸端摘要 |

补充判定细节：

- 异动核实成立：结果体现“现场与系统一致”并取得背景信息/偏离记录，且没有发现异常、读数不一致、无法确认、受限等冲突，也没有“基线抬升/下移不成立、尚未确认”等否定或不确定结论。只写“原因未明”不自动否定异动成立。
- 排查仅选“无法确认”且没有明确实施受阻时，可能仍走 D09/D10；但如果被记录识别为未完成，提交“效果观察”会被阻止，须先补全工作或明确处理剩余事项。这是现有原型校验，不应演示成观察已成功创建。
- 复查有异常回“决策中”，无匹配异常回“结果处置”；若复查未完成，D04/D05 优先。
- “不适用”表示本轮无需执行；“未完成”才需补做。汇总或备注写明缺备件、等停机等受阻情况，也会计入未完成判断。

## 3. 共用派发、执行与报告流程

### 3.1 轮机长派发

1. 从态势“智能关注”、事件列表或任务中心的决策入口进入事件；初始阶段查看“初始信息 / 数据观测 / 证据资料 / AI排查建议”。
2. 点“填写决策”，选允许的派发动作；查看对应待派任务方案，核对范围及步骤，必要时通过对话调整方案。
3. 选择“负责人”和未来的“要求完成时间”。**不再填写安排范围与依据**；“处理依据与安全实施前提”保留为选填，没有已核对复选框。任务采用确认时已审阅方案的范围和步骤。
4. 提前维保还要选择维保计划和有效靠港窗口，完成时间须在窗口内。确认后生成独立执行任务，执行人收到任务，轮机长从“我派发的”跟进。

### 3.2 轮机员填写与轮机长查看进度

1. 切换被派人员，从左侧“任务”→“待我处理”打开任务。
2. 逐步选择实际结果，备注选填；维修四组为“作业准备与安全隔离 / 实施维修与过程记录 / 复装与分阶段试验 / 交接与效果观察”，备注位于作业反馈下方并铺满宽度。方案经修改时以实际派发步骤为准。
3. 填写一部分后切回轮机长：可见已填写数量、更新时间、原派发步骤和此前正式回交记录。**尚未提交的备注正文只对执行人可见；并非逐步自动正式回传。**
4. 执行人到“汇总提交”，填写“原因判断与排查结论”或“实际措施、复测结果与剩余事项”，点击“提交排查报告 / 提交维修报告 / 提交维保报告 / 提交复查报告”。填写完步骤本身不会自动提交，必须点击提交按钮。

### 3.3 先回交人工事实，再补充 AI 分析

| 时点 | 实际表现 | 验收方式 |
|---|---|---|
| 点击提交且人工记录校验通过 | 立即保存逐项结果、备注、汇总结论和报告；轮机长收到回交提醒，事件进入决策/结果处置 | 保持 AI 生成中，另一个同源页签切轮机长打开任务及报告，能读到现场事实 |
| AI 生成中 | 任务页显示进度与生成片段；人工事实可审阅 | 原始反馈不被流式片段改写 |
| AI 成功 | 补充同一份报告的 AI 分析，报告 ID 不变，不重复创建提交记录 | 比较报告原始记录与更新后分析 |
| AI 失败/中断 | 事实报告仍已提交，工作完成情况保留；任务页显示失败原因 | 当前执行人从该任务页点击“重新生成报告” |
| 重试成功 | 补充原报告，不重复回交，不产生新任务 | 核对报告数量与提交次数未增加 |
| AI 未结束，轮机长已另派任务/闭环 | 停止旧轮次生成；迟到结果不覆盖当前状态 | 旧事实报告保留，不再对历史轮次重试 |

当前失败提示与重试按钮位于**任务详情**，报告正文不会单独插入完整技术错误日志。轮机长可看失败状态，重试由当前任务的执行人操作；不是任意历史报告都能重新生成。任务详情可逐项回看回交结果，点“查看排查/维修报告”直接打开本次报告；事件中也可从本轮“阶段报告”查看。

## 4. 效果观察：创建、到期报告与后续决定

1. 排查/维修/维保正式回交后，在允许的决策阶段选择“效果观察”。必须先处理未完成工作。
2. **只需填写未来的“计划汇报时间”**；“关注信号或现象”、展开后的可比工况、覆盖限制、提前介入情况均选填。没有“决定依据与后续安排”，不做 AI 预填。
3. 若配置数值提前介入，需要选择信号、持续高于/低于及有效数值阈值；近 15 分钟内、确认本轮计划之后的连续 3 个有效采样满足条件时提前出报告。纯文字提前介入描述不会自动转成数值规则。
4. 确认后原事件为“已转效果观察”，产生带来源任务和报告关联的独立观察事件；没有新增轮机员任务。点击关联入口打开观察事件。
5. 保持原型页面打开。默认每 30 秒模拟采样刷新时检查到期；后台页签可能被浏览器节流。关闭页面后没有服务器定时任务，再打开会检查已到期观察。当前观察数据为本地模拟源，不是实船实时采集。
6. 到期生成一份“观察报告”，包含计划/实际汇报窗口、采样记录、覆盖情况、工况和来源限制。没有有效数据也出报告，但结论是证据不足，不会自动认定恢复。重复刷新不重复生成本轮报告。
7. 轮机长收到待审阅提示，从当前观察阶段“阶段报告”选择本轮“观察报告”，也可从报告列表查看。到期汇总本身由系统生成，不依赖额外 AI 请求成功；另行更新 AI 观察建议时，失败可重试，不影响已生成观察报告。
8. 到期后：可再次选“效果观察”设置下一次时间（在同一观察事件追加新轮次，上一轮报告保留），或派复查；核实观察还可派维修。确认结束时填写闭环依据。按当前既有规则，在观察事件闭环会一并闭环其明确关联的原事件/观察链，其他无关事件不受影响。

## 5. 四条推荐主线与可复制的演示输入

以下示例先用于核对方案，再用于执行反馈；不能把未做的步骤预填成完成。选择独立验收副本测试互斥分支。

## 事件一：二缸报警与喷射控制核实

处理链：ICU 液压活塞卡滞的现场发现 → 批准针对性处理 → 维修回交 → 观察与人工关闭。原有报警与历史证据保持原样。

| P19 条件变化 | 等待中，执行人反馈范围/条件有变化 | 填核对情况并取消原范围不变选项 | 回交轮机长核对，任务保持等待，不自行扩大范围 |
| P20 终止剩余工作 | 等待中或未完成报告后 → 终止未执行部分 | 终止依据 | 任务终止，事件待后续决定；再选闭环或派复查 |
| P21 带剩余事项闭环 | 未完成报告后 → 说明剩余事项并闭环 | 决定依据 + 剩余事项处置与承担人 | 保留未完成事实并归档，不能标作全部完成 |
| P22 恢复后再次提交 | P17/P18 恢复后补做并提交 | 更新实际结果和汇总 | 原任务第 2 次报告，新旧提交可分别打开；旧 AI 分析不沿用为本次事实 |
| P23 上报岸基 | 任何阶段点右上角上报岸基 | 展开核对基础报告；4 项补充全选填 | 确认后显示“已上报岸基”并进入事件内上报页签；正文整合过程，可切换历次快照；原型流程，事件状态不变 |
| P24 AI 失败重试 | 提交反馈后模型失败/中断 | 当前执行人任务页 → 重新生成报告 | 人工报告始终存在，成功补充同一份报告 |
| P25 报告补充 | 未闭环且允许补充的本人报告 → 通过对话补充报告 | 输入补充事实，审阅修订稿，再“确认补充并更新报告” | 确认前不覆盖，确认后保留原稿与修订记录；普通聊天不算修改报告 |
| P26 计划修改/失败 | 派发前查看任务方案 → 通过对话修改任务 | 输入范围/步骤调整，核对结果 | 有效修改生效；失败保留已有方案，无就绪方案则不能派发 |
| P27 权限与进度 | 分别派给大管轮、二管轮；轮机长查看 | 按 3.2 操作 | 各人仅执行本人任务；轮机长看填写数量、提交后逐项事实及报告 |
| P28 观察链闭环 | 独立观察事件 → 闭环 | 明确人工结束依据 | 明确关联链同时闭环；其他三条独立案例不变 |

操作 P24 时，可由维护人员在独立测试环境制造模型失败；不要改动真实 AI 配置或清理业务数据。自动回归使用可控的失败请求验证，不依赖线上模型偶发失败。P09 要注入独立测试采样才能确定性触发；日常演示若没有满足阈值的采样，不承诺立即出现提前报告。

## 7. 完成检查与限制

- 决策动作共 11 个：派发排查/继续排查（investigate）、确认误报（false）、派发维修/剩余维修（repair）、提前维保（maintenance）、派发复查（recheck）、等待（wait）、恢复（resume）、终止（terminate）、效果观察（observe）、闭环（close）、上报岸基（shore）。不同按钮文案可能对应同一动作。
- 原事件 ID 不变；派发产生新任务；等待后恢复不换任务 ID；同一任务多次提交有分别的报告；效果观察是独立关联事件。
- 人工报告先回交，AI 生成失败不推翻提交；未提交草稿正文仍仅执行人可见。资料缺失、原因未知、未执行、无需执行分别记录。
- 从左侧任务下方“报告”或 `/#/reports` 查看报告，详情可“下载 Markdown”；观察报告也在列表保留。无需按旧截图寻找“同步岸基/待岸基接收”等已更新文案。
- 角色为原型本地身份；数据在同源浏览器本地保存，没有生产身份系统、岸端真实发送或浏览器关闭后的后台定时执行。
- [四事件报告填写案例](./四事件报告填写案例.md)及旧生成报告是历史参考。旧 `scripts/generate-script-reports.mjs` 按旧标题与固定分支解析，未适配本脚本，不用于证明当前流程跑通。
- 本版依据 `lifecycleDecisions.js`、`eventLifecycle.js`、`taskReportGeneration.js`、`lifecycleObservation.js`、`observationReports.js` 以及当前页面核对；没有承诺模型每次生成相同文本或所有人工路线已逐一实机演示。
