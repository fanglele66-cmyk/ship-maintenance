# 消息流配置与组件复用

## 当前落地范围

主机设备态势（`device.situation`）已使用 JSON 配置：每日健康回顾、3#缸状态提醒、轴承与冷却系统关联信息。消息内容、状态判断和按钮行为沿用现有原型。

船舶概览、关注事项、待办、传感器、效果观察仍由原来的数据逻辑产生消息，但已复用通用渲染组件，通过 `kind` 兼容层接入。它们尚未逐页改为 JSON。知识库的 `KnowledgeAIPanel.vue` 是独立面板，本次未迁移。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `src/message-flows/device-overview.json` | 设备概览消息顺序、稳定 ID、类型、展开状态 |
| `src/message-flows/deviceSources.js` | 根据业务状态提供消息内容；过滤已有重复预设消息，保留实际对话 |
| `src/message-flows/resolveMessageFlow.js` | 校验配置并绑定数据；兼容旧消息类型 |
| `src/components/messages/MessageRenderer.vue` | 消息外壳、类型分发、时间和标签、操作插槽 |
| `src/components/messages/SceneMessage.vue` | 每日摘要卡片、提醒、分析报告、展开收起、消息操作按钮 |
| `src/components/messages/FeedbackRecordMessage.vue` | 反馈及草稿确认记录 |
| `src/components/Phase2Assistant.vue` | 选择场景、合并对话、输入发送、业务动作分派和滚动 |
| `src/styles/conversation.css` | 通用对话视觉样式 |

组件内不直接修改业务状态、不执行路由跳转。`action` 和 `confirm-record` 事件交由宿主处理。当前 `notice` 与 `report` 共用展开报告组件，后续可以在分发层单独替换提醒样式。

## 配置契约（版本 1）

```json
{
  "version": 1,
  "scene": "device.situation",
  "messages": [
    {
      "id": "device-daily-review",
      "type": "dailyBrief",
      "source": "dailyReview",
      "expanded": false
    }
  ]
}
```

- `scene`：场景标识。目前宿主显式选择配置，不是自动路由注册表。
- `messages`：数组顺序就是展示顺序。删除或移动条目可调整预设流，不会删除已保存的实际对话。
- `id`：同一配置内必须唯一，供 Vue 保持组件身份。改变排序时不要改变 ID。
- `type`：`text`、`dailyBrief`、`notice`、`report`、`feedbackRecord`、`inquiry`。
- `source`：数据源对象中的显式键名。不能填表达式、脚本或任意状态路径。
- `content`：静态消息对象；不填写 `source` 时可使用它。若两者同时填写，以 `source` 为准。
- `expanded`：可选布尔值。明确配置时优先；未配置时由宿主默认规则决定，每日推送默认收起。用户可继续手动展开。

解析器拒绝未知类型、缺失数据源、重复 ID、错误展开状态及不支持的版本。新增页面应在开发和测试时修正错误配置，不要静默吞掉错误。

## 消息内容字段

共同字段：`role`（`assistant` / `user`）、`at`、`demoLabel`；`stageId` 可用于阶段滚动定位。

| 类型 | 内容字段 |
| --- | --- |
| `text` | `text` |
| `dailyBrief` | `title`、`paragraphs`、可选 `question` / `actions`；第一段为默认三行摘要 |
| `notice` / `report` | `title`、`paragraphs`、可选 `question` / `actions` |
| `feedbackRecord` | `title`、`task`、`records`；兼容草稿仍需 `kind: "recordDraft"` 及原确认状态字段 |
| `inquiry` | `text`、`fields`、`values`、`status`；可选 `hint`、`submitLabel`、`busy`、`submitError`、`submittedAt`、`receiptText`、`inactiveReason` |

### 通用询问组件

`InquiryMessage.vue` 只渲染、校验和发出事件，不读业务 Store、不跳转、不创建事件。`inquiryFields.js` 负责字段契约；`attentionInquiry.js` 负责当前现场核实场景的数据绑定。样式统一放在 `conversation.css`。

```json
{
  "id": "stable-request-id",
  "type": "inquiry",
  "role": "assistant",
  "text": "请补充现场记录。",
  "status": "pending",
  "fields": [
    {"key": "reading", "label": "读数", "type": "number", "required": true, "min": 0},
    {"key": "state", "label": "现场状态", "type": "select", "options": [{"label": "未见异常", "value": "normal"}, {"label": "发现异常", "value": "abnormal"}]}
  ],
  "values": {"reading": 432},
  "submitLabel": "提交记录"
}
```

- 字段类型：`text`、`textarea`、`number`、`select`、`multiselect`、`date`、`datetime-local`、`boolean`。字段均包含唯一 `key`、`label`、`type`；可选 `required`、`value`（默认值）、`placeholder`；数字可设置 `min/max`；枚举使用 `options: [{label,value}]`。
- `values` 优先于字段默认值；枚举保留原值类型，多选为数组。必填布尔字段表示必须勾选确认。
- `update-inquiry`、`submit-inquiry` 均返回 `{messageId,values}`，由 `MessageRenderer` 转发。宿主保存草稿、校验当前业务要求并调用原有反馈方法；组件不自行宣布业务完成。
- `pending` 可填写；`submitted` 展示原字段的只读回执；`inactive` 禁止提交。支持宿主提供提交中和失败提示，不内置网络请求。
- 当前仅实装关注档案详情的现场核实。左侧保留行动摘要及定位入口，不重复显示表单；已关联事件仍进入原事件检查。
- 询问属于档案的主会话，新建及历史会话不复制询问。左侧定位入口切回主会话；已提交回执可回看。本次草稿在当前助手实例中保留，刷新页面不保证恢复，正式持久化后续设计。
- 普通对话不完成核实，提交核实不自动创建事件。完整对话内容本次未重构。

`paragraphs` 为 `{ "label": "当前结论", "text": "…" }` 数组。`actions` 为 `{ "id": "item:drift", "label": "查看关注材料" }` 数组。`records` 为包含 `label`、`result`、可选 `note` / `attachments` 的数组。内容以 Vue 文本插值渲染，不使用 HTML 字符串执行或 `eval`。

## 新页面接入步骤

1. 在 `src/message-flows/` 增加场景 JSON，并填写固定 ID、类型和顺序。
2. 增加数据绑定函数，返回以 `source` 命名的消息对象。动态条件、设备数据和业务状态判断写在此函数中，不写入 JSON。
3. 在宿主 `computed` 中调用解析器，确保状态变化会重新计算；然后合并用户对话记录。
4. 使用 `MessageRenderer`，将事件连接到宿主动作处理函数；需要页面专属操作时使用 `actions` 插槽。
5. 核对初始态、状态变化、展开收起、操作跳转及历史记录合并，避免预设消息重复。

```js
const displayedMessages = computed(() => [
  ...resolveMessageFlow(pageConfig, pageMessageSources(store)),
  ...conversationRecords.value
])
```

```vue
<MessageRenderer
  v-for="(message, index) in displayedMessages"
  :key="message.id || index"
  :message="message"
  :expanded="index === displayedMessages.length - 1"
  @action="handleAction"
  @confirm-record="confirmRecord"
/>
```

实际对话应逐步补充稳定 ID；当前旧记录沿用索引回退。预设流与实际对话分别管理，配置不负责保存或覆盖对话记录。

## 现有动作标识

`Phase2Assistant` 显式处理：`device`、`todo`、`item:<事项ID>`、`todo:<待办ID>`、`ask:<问题文本>`。标识只引用既有操作，不执行任意代码。新增动作需同时补充宿主处理分支；不应只在 JSON 中新增一个无法执行的按钮。

## 样式与验证

保留外层灰底与白色工作区。每日推送使用轻卡片，普通对话保持连续阅读；不要在消息卡片内部再套背景面板。样式统一在 `conversation.css` 中维护。


## 设备页签与会话边界

设备概览、传感器数据、关注事项、维保计划、待办任务、设备履历是同一个设备页面的同级页签，共用 `device.situation` 消息流和设备对话记录，不应分别创建六套配置。切换页签或列表分类不会自动选择第一条事项作为对话主题，也不会清空当前设备输入。

进入具体关注事项、维保计划或效果观察详情时，才接续对应事项上下文；返回列表恢复设备会话。跳转到待办中心则使用独立的待办会话。以后扩展配置时，应以“设备页面 / 事项详情”等实际会话边界选择配置，而不是每个页签一个配置。

## 历史对话与智能体边界

`src/composables/useAgentConversations.js` 保存“智能体 → 会话 → 消息”结构。每个智能体首次进入时创建第一条当前会话，并预置两条演示历史；之后恢复其上次选中的会话。只有点击“新建对话”才新增会话。页签、筛选、页面切换及自动推送不新建会话。

`ConversationHistory.vue` 接收 `conversations` 与 `currentId`，发出 `select` / `new-conversation`。右上角入口打开当前智能体的列表，每项展示标题、最近更新时间和末条消息摘要，当前会话有标识，按最近更新时间倒序。点击后恢复整段对话并关闭列表，左侧页面不跳转。

每条会话独立保存 `messages`、`draft` 和 `updatedAt`。标题由第一条用户消息生成。新建或切换时输入草稿分别保留，重新进入页面仍恢复当前会话；整个原型的记录保存在本次运行的内存中，刷新后恢复演示初始数据。

主机六个同级页签共用 `device:main-engine-1` 智能体；船舶态势、事项详情、待办等宿主有独立智能体标识。知识库使用 `knowledge`，不再按筛选条件归档成新会话，也不会列出其他智能体的对话。

Phase2 的第一条会话继续承接原有配置推送及业务记录，新建/历史会话使用各自消息；新增回复绑定到发送时选定的会话。知识库的异步回复也绑定发送时的会话，避免回复过程中切换会话导致串消息。生产接入时应将这个内存注册表替换为服务端会话接口，补充消息 ID、存储与权限，不需改变历史列表组件契约。

原型界面仅隐藏没有消息且没有草稿的空会话。已有内容的会话始终保留入口；未形成用户标题时，使用首条消息的主题或文本作为展示标题，避免切换后无法返回。新建入口与历史入口并排放在助手右上角，使用一致的图标按钮，历史面板内部不重复放置新建按钮。
