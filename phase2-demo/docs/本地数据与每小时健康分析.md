# 船端 2.0：连续数据副本与每小时健康分析

本轮接通工况态势、主机测点与趋势、主机设备健康研判和详细研判。事件中心的演示案例仍独立保存，工况态势不再叠加预置的报警、预警，也不根据当天日期把事件移到“刚刚发生”。现在接入本地账号登录与管理员删除服务；已有事件、任务内容仍沿用浏览器工作空间，删除记录由后端持久保存。

## 数据和时间

输入为 `ship_sop/ship-data-collector/ship-data-collector/data/ship.db`，使用 SQLite 只读连接和 backup 获得一致性副本，包括已提交的 WAL 数据。原数据库不改动。

用户要求剔除空缺时间，因此不再使用简单的整体日期偏移。当前规则是：

1. 按原始时间排序，保留完整的 59 点采样帧；不完整帧剔除，不补造传感器值。
2. 每组原始值在回放轴上占 12 秒，相邻采样严格连续。12 秒来自所选数据段的主采样间隔；通过 `--cadence-seconds` 可以显式调整。
3. 将指定历史锚点之前最后一条采样对齐初始化时刻。之前的数据用于历史窗口，之后的数据随当前时钟逐步可见。所有查询截止到服务端当前时间，未来记录不能提前返回。
4. 原时间保存为 `source_time`，原采样间隔保存为 `source_gap_seconds`；`replay_clock`、`manifest.json` 保留映射依据。刷新浏览器和重启服务不会重排时间；数据到尾部时提示用尽，不自动循环或伪装为新数据。
5. AIS 和气象通过同一主机时间映射换算。落在被剔除的长空档内、或主机覆盖区间外的记录不进入回放。没有 AIS 的时段显示缺失，不填造航速。

去空档后的时间不是原始航次持续时间，不能据此反推真实变化速率。当前功率负荷没有对应测点，显示 `—`；燃油指令不替代负荷。原型模拟器仍用于未接入的辅机等页面，不再覆盖主机和航速。

点位身份和名称继承旧船端映射，单位以这批数据库的采集配置为准：部分压力是 MPa，不能照搬接口映射中的 bar；无单位泄漏信号也不能改称流量。所有数值保持不变。

初次导入验证（停机压缩前，2026-11-10）：主机 2,094,567 帧，AIS 101,939 条，气象 8,788 条；源数据大于 60 秒的断点 7,700 处。全量相邻主机采样最小/最大间隔均为 12 秒，非 12 秒间隔数为 0。起始历史锚点为 `2026-07-04 12:00:00`；当前副本可持续回放到 `2027-02-21 09:16:55`。这些日期属于本次副本，重新初始化会重新生成。

## 停机段压缩（2026-11-10 更新）

后端停止后执行 `npm run data:compact`。只处理本项目复制库：转速 0–5 rpm 的连续记录视为停机；超过 24 小时的段落保留前后各 12 小时，删除中间样本。同步删除被删区间的 AIS、气象记录并重新映射时间，传感器值与 `source_time` 不改变。若当前锚点被删除，续接到下一条保留记录并对齐本次执行时间。

脚本先生成新数据库、验证全量 12 秒间隔和最长停机段，再原子切换 manifest；旧副本和旧 manifest 保留。重复执行同样规则直接返回已有结果。数据源 `ship_sop` 数据库全程只读。本次压缩 76 段，删除 411,646 个停机采样帧、14,360 条 AIS 和 1,372 条气象记录；保留 1,682,921 个采样帧，最长停机 86,400 秒，非 12 秒相邻间隔为 0。保留值及原始时间与压缩前副本全量关联比对，差异为 0；更新后的时间范围为 `2026-06-11 16:51:23` 至 `2027-01-31 10:35:23`。

新增 `run_local_health.py` 负责数据库到标准 `pointDataList` 的转换；实际统计仍调用原 `run_engine_health.run` 和 `changhang.analyze_health`，没有另造一套健康评分。输入是当前截止时间前 6 小时、12 份半小时文件。

当前版本分析完整六小时连续窗口，不再截取最后一个源片段。原始时间和拼接点保留在内部 coverage，供开发追溯；正常研判只描述当前工况、关键数值和关注建议，不显示回放、数据构建、局限说明等技术叙述。停机、确实无测量值和未确认故障仍按事实表达。

模型读取 `references/local-report.md` 和 Skill 计算事实，生成摘要、一个关注建议与 Markdown 正文。模型不能改写数值、评分或事实，不创建事件、不派发任务。模型关闭/失败时保留确定性 Skill 结果，界面明确说明，绝不用演示报告兜底。

## 本地服务与调度

```text
SQLite 连续副本 → /api/data/situation → 工况态势 / 主机实时测点 / 24 小时趋势
               → 每小时 6 小时窗口 → 原 ship-engine-health → 模型整理
               → health-latest.json + health-latest.md → /api/data/health → 主机研判
```

后端启动后首次执行，然后每个北京时间整点执行；检查间隔 30 秒。调度记录在 SQLite 中持久化，以小时去重，支持多个进程争抢同一任务、超时租约恢复、失败后五分钟重试（每小时最多三次）。进程停机时不会执行，重新启动会补做当前窗口，不批量生成停机期间的旧报告。关闭浏览器不影响后端任务。

去重键还包含数据清单、Skill、提示词与测点配置的版本摘要；适配文件变更后重启服务会重新生成当前窗口，避免继续显示旧单位或旧规则的报告。同一数据目录的不同服务进程共用一把分析租约。

Skill 原输出目录保留最新十份计算产物；工作输入每轮替换。每个完成的小时另归档完整输入、Skill 结果和报告到 `health-history/<小时编号-版本>/`，不会随下一次分析覆盖。历史归档会持续占用磁盘，清理前应按需另行备份。模型失败不会抹掉本轮 Skill 计算结果；Skill 整体失败不会覆盖上次成功报告。页面展示报告真正的完成时间、分析范围和过期状态，不用测点刷新时间冒充报告更新时间。

运行产物位于 `.local-data/`：

- `ship-continuous-24h.db`、`manifest.json`：当前连续数据和映射说明。
- `ship-replay.db`、`manifest-before-stop-compaction.json`：停机压缩前的副本和清单，保留以便恢复。
- `stop-compaction-receipt.json`：本次停机压缩及全量验证记录。
- `jobs.sqlite`：调度运行记录。
- `accounts.sqlite`：账号密码摘要、登录会话、删除事件编号及操作人/时间。
- `accounts-initial.json`：首次创建的四个账号和随机初始密码；只保存在本机，不提交 Git。
- `health-history/<小时编号-版本>/`：每小时完整产物，`report.md`、`report.json`、`skill-result.json`、`sensor-raw-data/`。
- `workspace/input/sensor-raw-data/`：当前检测窗口。
- `workspace/result/engine-health/outputs/`：经原 Schema 校验的健康结果。
- `health-latest.json`、`health-latest.md`：前端读模型和本地研判文档。

接口只允许本机同源访问，要求 `x-engine-room-client: local-ui`；原始数据库、Skill 工作空间和模型密钥不作为静态文件发布。数据库与运行产物已加入 Git 忽略；GitHub 提交代码、Skill、配置和说明，不上传约 GB 级原始数据库或本机模型密钥。

## 启动和验证

当前环境使用 Node.js 24（内置 SQLite）及 Python 3.11。新环境安装 npm 依赖和 `requirements-local.txt`；模型沿用页面设置 / `.local-ai/config.json` / CC Switch 配置，不在仓库保存密钥。

在 `phase2-demo` 执行：

```powershell
npm install
python -m pip install -r requirements-local.txt
npm run data:prepare -- --source 'D:\zstech\ship_sop\ship-data-collector\ship-data-collector\data\ship.db'
npm run data:compact
npm run build
npm start
```

打开 `http://127.0.0.1:5173`。`PORT` 可以更换端口，`SHIP_PYTHON` 可以指定 Python，`SHIP_DATA_DIR` 可以指定已有数据目录。已有 manifest 时导入脚本拒绝覆盖，避免重置正在运行的数据时钟。

开发使用 `npm run dev`，Vite 会启动同一数据服务和调度。已有数据副本的情况下不用再次执行导入。`npm run health:run` 执行当前小时尚未完成的任务，遵循同一去重规则。

```powershell
npm run data:test
python -m unittest discover -s tests -p test_local_data.py
python -m pytest .claude/skills/ship-engine-health/tests -q
npm run auth:test
node --test tests/account-workspace.test.mjs tests/demo-timeline.test.mjs
python -m unittest discover -s tests -p test_stop_compaction.py
```

本轮不声称已完成免安装的解压即用发行包；该发行包仍需捆绑运行时、数据副本和模型配置引导。当前本地后端、数据和 Skill 已可实际运行。
