# 事件反馈与阶段推进规则

2026年10月12日：按用户确认修正“结果必须符合预设答案才能提交”的问题。

- 检查项完整且结果属于该项选项时，允许提交发现异常、未见异常、无法确认、条件不足等实际结果。原文、备注和附件名称作为反馈快照留存；重复提交相同记录不重复追加回执。
- 保存不等于阶段推进。多处异常或证据不足时仍保存成功，提示继续研判，不直接跳进预设单一部件维修。
- 缺少必填检查结果时不提交；实际维修未完成、验收未确认仍不能作为处理完成推进。
- `src/mock/eventFeedbackRules.js`统一定义检查选项及原型分支条件；`TodoDetailPad.vue`只负责展示、完整性检查和提交结果提示，Store执行保存与推进边界。Stage及Task定义仍来自现有场景数据，真实AI研判、其他处置分支、可视化流程配置和后台发布未实现。
- 当前保留既有成功故事分支，不能把选项组合判断当作真实根因确认算法。真实系统应由人员及分析证据确认处置方向，不能要求现场结果迎合固定故事。
- 业务更新时间在创建、推进及实际提交反馈时更新，普通输入草稿及追问不更新。

新增 `tests/event-feedback.test.mjs`，覆盖两处异常保存不推进、无法确认保存、回执快照、重复提交去重、缺失反馈拦截以及既有支持分支推进。浏览器已按“两项发现异常＋分别备注”验证右侧出现已提交回执，维修仍待接续。

仍为本地内存原型；刷新会恢复初始记录，未连接持久化或真实诊断模型。
