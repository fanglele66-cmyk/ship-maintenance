# 船端异常上报固定提示词

## 完整模板

```text
提交异常报告
船舶ID：<ship_id>
ser_no：<后端生成的本次人工上报流水号>
发送端：<船端|岸基；可省略，省略时默认船端>
设备：<页面设备中文名称>
系统：<页面系统中文名称；多个用顿号、中文逗号或英文逗号分隔>
关联传感器：<页面传感器中文名称；多个用顿号、中文逗号或英文逗号分隔>
异常开始时间：<北京时间无时区ISO 8601，例如2026-08-10T00:00:00>
异常结束时间：<北京时间无时区ISO 8601，例如2026-08-11T00:00:00>
异常描述：<现场观察到的异常现象、持续情况和当前状态>
图片：<图片ID；多个使用英文逗号分隔；没有填无>
Skill：$ship-manual-anomaly-analysis
```

## 固定规则

- 首行固定为 `提交异常报告`，末行固定为 `Skill：$ship-manual-anomaly-analysis`。
- `ser_no` 是必填行，必须紧跟在 `船舶ID` 后，只允许字母、数字、下划线和连字符；缺失、空白或格式非法时不得执行映射、在线取数或业务写入。
- `发送端` 是唯一可选行；如提供，必须紧跟在 `ser_no` 后且值只能是 `船端` 或 `岸基`。省略时默认 `船端`。
- `发送端=船端` 或省略时使用 `event_type=ship-manual`；`发送端=岸基` 时使用 `event_type=shore-manual`。两者都写入 `result/ai-anomaly/`，但不得互相去重或改写类型。
- 新订单按本次 `ser_no` 创建独立事件，事件 ID 固定使用 `ai-<ship_id>-<ser_no>-<event_start_YYYYMMDD_HHMMSS>`；不得因发送端、设备、系统、测点或时间连续而复用其他 `ser_no` 的事件。同一 `ser_no` 重试只返回自身既有事件；不同订单及不同发送端必须使用不同 `ser_no`。
- 字段顺序固定，字段名和值之间只使用全角冒号 `：`。
- 一条消息只提交一份异常报告，不混入进入排查或反馈动作。
- `船舶ID`、`ser_no`、设备、系统、关联传感器、开始时间、结束时间和异常描述必填。
- 设备、系统和关联传感器是用户权威输入：系统及传感器按输入顺序去重，每个名称独立唯一解析，传感器必须属于同一上报设备及任一已选系统。analysis result 与 active-events 的 `systemTypes[]/systemNames[]` 保留完整系统集合，`systemType` 仅兼容保留首个系统 ID。不得把“主机系统、燃油系统”等多系统输入改写成单个系统。查询必须保留全部上报传感器，超过 6 个也不截断；额外补点尽量使总数达到 2～6 个，AI 周期/OEM 的上限保持不变。
- 时间使用北京时间无时区字符串，格式为 `YYYY-MM-DDTHH:mm:ss`，事件时间和查询时间使用同一钟面值，不做加减 8 小时换算；历史带 `Z` 或偏移的输入继续兼容。
- 设备、系统和传感器可以是页面中文名称，但必须从当前 mapping 逐项唯一解析；不得按相似语义静默猜测。
- 数据覆盖门禁按原上报时间窗逐个校验已选传感器：每点有效数值样本的首尾时间跨度至少达到上报窗口时长的 50%。默认最多在线尝试 3 次；仍有缺点、覆盖不足、无有效数据或接口失败时停止，不创建或更新事件，不生成成功结果，不自动采用其他时间的历史 raw。没有算法候选但数据门禁合格时仍可分析。
- 图片为空时固定发送 `图片：无`。有图片时只发送图片 ID 字符串，多个用英文逗号分隔；禁止发送本地路径、文件名或三元附件对象。解析后保存为 `image_ids[]`，本 Skill 不移动或删除图片。
- 后端应原样发送完整模板；Agent 不从聊天历史补齐本次缺失字段。

该格式沿用 `markdown/船端页面字段标记.md` 的“固定中文动作、全角冒号、单动作、末行 Skill”约定，并沿用 `markdown/0801OpenClaw后端工作空间初始化与会话创建提示词.md` 的显式 Skill 调用和后端校验产物规则。
